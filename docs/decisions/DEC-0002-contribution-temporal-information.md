# DEC-0002: Contributionの時間情報を解釈前のContextとして取得する

## Status
Accepted

## Context
S11を先行検討した結果、
ContributionからDiscoveryおよびValueをどのように形成・変換するかは、
現時点では未確定であることが明確になった。

例えば、`XX城址公園：現在（Discovery）`に
`憩いの場：通年（Value）`がある場合、
「中世のXX城」という情報は、
別Discoveryである`XX城：中世`にも、
XX城址公園に紐づくValueにも、
その両方にもなり得る。

時間情報には、少なくとも次の二つの意味グループがある。

- 「いつの話か」：Discoveryとして成立し得る対象の存在時期・対象年代を判断する材料。現在、過去、未来、不明のほか、中世、戦国時代、昭和30年代、1600年頃等の表現がある
- 「いつ見たり体験したりできるか」：Valueになり得る時間条件を判断する材料。季節（通年、春、夏、秋、冬）、時間帯（朝、昼、夕方、夜）、詳細な時期・期間・時刻等があり、これらは組み合わせられる

S04でこれらの帰属を確定すると、
後段で必要となる解釈の可能性やユーザーが提供した情報を失うおそれがある。

## Decision
S04では、入力された時間情報のDiscoveryまたはValueへの帰属・変換を確定しない。

S04の責務は、S11以降でContributionを解釈し、
Discoveryおよびそれに紐づくValueを抽出・判断するために必要な情報を、
欠落させず取得して渡すこととする。

「いつの話か」について、
対象年代・時期の詳細入力は、検索可能なサジェスト入力と自由入力を組み合わせる。
候補選択を強制せず、ユーザーの原文を保持する。
表記揺れの統一や期間への正規化はS04で強制せず、
`戦国期`から`戦国時代`への統一や、
`昭和30年代くらい`のシステム上の期間への解釈等は、
必要に応じてS11以降でAIによるサジェストとユーザー確認を行う。

「いつ見たり体験したりできるか」について、
S04では季節、時間帯、「詳しく指定」を入力できるようにする。
「詳しく指定」では、`4月初旬`や`7/15〜8/31`等の毎年のおおよその時期、
`2027/4/3〜2027/4/10`等の特定の日付・期間、
`17:00〜21:00`等の時間のFrom-Toを扱えるようにする。

詳細な時期・期間入力は、
共通コンポーネント`C24 時期・期間入力（Time Period Input）`として切り出す。
C24は入力情報がDiscoveryまたはValueのどちらに帰属するかを判断しない。
当初はDialogでの利用を想定するが、Dialog専用コンポーネントにはしない。

S11のMock作成は、
ContributionからValueおよびDiscoveryへの変換設計を再開するまで保留する。

## Deferred / Open Questions
S04の入力項目が重いか、
時間情報の入力をS11へ寄せるか、
S04とS11の間に入力補完を設けるか、
入力自体をAIとの対話式にするかは確定しない。

これらはMockおよび実装以降に評価し、変更できるものとする。
変更する場合も、後段の解釈に必要な情報を失わないことを優先する。

ContributionからValueおよびDiscoveryを形成・変換する具体的な規則も、
本Decisionでは確定しない。

## Revisit conditions
S11のMockまたはContributionからValueおよびDiscoveryへの変換設計を再開する場合、
S04のMockや実装によって入力負荷または情報不足が明らかになった場合、
このDecisionを再評価する。
