# Decision Log

このディレクトリには、ex-day の開発における重要な意思決定と、
その判断に至った背景を記録します。

## 目的

仕様や設計の最終結果は各種定義書に記載します。

一方、定義書だけでは失われる
「なぜその判断をしたのか」
「どのような選択肢を検討したのか」
「何を今後の検討事項として残したのか」
を Decision Log として記録します。

これにより、人間および異なるAI・作業環境間で、
判断の背景を必要に応じて参照できるようにします。

## 記録するもの

すべての議論を記録する必要はありません。

以下のような、後から判断背景が必要になる可能性のある決定を記録します。

- プロダクト・ドメインに関する重要な判断
- UI/UXに関する重要な判断
- 技術・アーキテクチャに関する重要な判断
- AIとの協働方法・開発プロセスに関する重要な判断
- 将来再検討する可能性がある判断

## 基本構成

各Decisionには、必要に応じて以下を記録します。

- Status
- Context
- Decision
- Reason
- Alternatives
- Consequences
- Deferred / Open Questions
- Revisit Conditions
- Related Issues / PRs

すべての項目を必須とはしません。
判断を後から理解するために必要な情報だけを残します。

## 命名

`DEC-NNNN-short-description.md`

例:

`DEC-0001-introduce-decision-log.md`

## 参照方針

現在有効な仕様については、Decision Logではなく各種定義書を正とします。

Decision Logは、仕様の背景や判断理由を確認する必要がある場合に参照します。

## Decision Logの位置づけ

Decision Logは、AIのMemoryや過去の会話履歴を代替するものではありません。

すべての会話や検討過程を保存・再現することを目的とせず、
後続の作業で必要になる可能性のある重要な意思決定と、
その判断背景を共有するための記録として利用します。

必要なContextは、現在の定義・Issue・関連するDecision Logから
作業ごとに組み立てることを基本とします。
