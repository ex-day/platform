# DEC-0010: 会話の重複を歓迎し、Discoveryの乱立を避ける。投稿確定時に認証を求める

## Status

Accepted

## Date

2026-09-25

## Context

新規投稿の動線（Issue #67）を検討する中で、次の2点を決める必要が生じた。

### 1. 同じ問い・同じ話が繰り返し投稿されることの扱い

DEC-0005 決定3は、「探索開始時点で明白な単純重複は抑制し、既存の議論やDiscoveryへの参加を促す」とし、MVPスコープ7章にも「明白な単純重複には既存の会話への参加を案内する」と反映されている。

この決定は、Contributionを投稿時にDiscoveryへ紐付けないと話題が乱立する、という当時の前提に立っていた。その後、DEC-0007〜DEC-0009により、次の仕組みが整った。

- Postは会話の中の発言であり、投稿後に話題（Topic）・発見の仮説（DiscoveryHypothesis）として解析される
- 仮説を既存のDiscoveryと突き合わせ、補完・類似・同一・派生の提案（Proposal）を出す
- ユーザーの「一緒では？」は判断ではなく、重なりの手がかりとして受け取る
- 同一と判断されたDiscoveryは統合でき、探索過程は消さない（DEC-0005 決定5）

一方、知恵袋のような投稿型サービスでは、既に解決済みの同じ質問が繰り返し投稿される。これを許容すればコンテンツの量は増えるが、中身が分散して質が下がる。逆に、投稿前に「同じ問いが既にあるか」を確かめさせると、投稿の動機が下がる。

### 2. 匿名投稿を許可するか

MVPスコープでは、未ログインでも投稿の入力を始められることとし、投稿確定時に認証を必須とするかはNon-blockingの未決事項としていた。DEC-0009で定めた候補の判断材料（関わった参加者の数、1人の参加者の1つの発言だけでは候補にしない原則）や、自分の発言の編集・削除、S09の再構成（#68）は、誰の投稿かを識別できることを前提としている。

## Decision

### 1. 会話の重複は歓迎し、Discoveryの乱立は避ける

**同じ会話が何度投稿されてもよい。ただし、Discoveryとしての乱立は避ける。**

| 段階 | 扱い |
|---|---|
| 投稿する前 | 止めない。既に同じ問い・話があるかを確かめさせない |
| 投稿した直後 | 似た既存のDiscoveryと、そのわかってきたこと（Finding）を示し、既存の会話に加わる選択肢を示す。加わるかどうかはユーザーが選ぶ |
| その後 | 同一の提案として判断を経て統合する（DEC-0009 決定7）。新しいPostは消さず、統合先から辿れるようにする（DEC-0005 決定5） |
| 見せ方 | TOP・検索等では、まとまったDiscoveryを見せる。重複した成立前のDiscoveryを前に出さない |

- 投稿した直後に既存のわかってきたことが見えることで、質問した人の目的（答えを知りたい）をその場で満たせるようにする。
- 投稿直後の表示は、「既に同じ質問があります」のように投稿を咎める言い方ではなく、「同じことを気にしている人がいます」「こんなことがわかっています」のように、関心を分かち合う言い方とする。具体的な文言は画面設計（#67）で決める。
- 同じ問い・話が繰り返し投稿されることは、その場所への関心の強さや、季節性の手がかりとして扱う（DEC-0009 決定9の問いへの「自分も気になる」と同じ性質）。
- 場所と時間を扱うex-dayでは、同じ問いでも時期によって答えが変わることがあり、新しい投稿者が新しい資料・視点を持ち込むこともある。そのため、同一かどうかは機械的に決めず、DEC-0007・DEC-0009の判断（発見・価値の一致で判断する）に従う。
- ユーザーによる「同じ話だ」という紐付けの操作は、画面上は「紐付けた」でよいが、内部では重なりの手がかりとして受け取り、提案と判断を経る（DEC-0006 決定3、DEC-0007 決定10）。

**DEC-0005 決定3との関係：** DEC-0005 決定3の「明白な単純重複は抑制し、既存の議論やDiscoveryへの参加を促す」のうち、**投稿時点での案内を、投稿直後の案内と、投稿後の統合に置き換える。** 「類似Discoveryがあることだけを理由に探索を閉じない」「既存の議論への参加を促す」という趣旨は維持する。

### 2. 投稿の確定時に認証を求める

- 投稿の入力は、未ログインでも始められる。
- 投稿を確定するときに、ログインを求める。入力した内容は、ログイン後に引き継ぐ。
- 匿名での投稿（アカウントを持たない投稿）は認めない。
- 画面上の表示は、本名ではなくニックネームでよい。「匿名で投稿できること」と「匿名で表示されること」を分けて扱い、後者は認める。

## Reason

- 投稿前に重複を確かめさせると投稿の動機が下がる。一方、DEC-0007〜DEC-0009で、投稿後に似たDiscoveryを見つけ、提案と判断を経て統合する仕組みが整ったため、投稿前に止める必要がなくなった。
- 投稿直後に既存のわかってきたことを見せれば、質問者の目的をその場で満たしつつ、既存の会話へ自然に誘導できる。
- コンテンツの量（会話の重複）と質（Discoveryの乱立の回避）を、投稿と見せ方・統合という別の段階で扱うことで両立できる。
- 同じ問いの繰り返しは、関心の強さ・季節性という、ex-dayにとって価値のある手がかりになる。
- 匿名投稿を認めると、1人が繰り返し投稿したのか複数の人なのかを区別できず、DEC-0009の候補の判断材料（参加者の数、1人1発言の原則）が機能しない。自分の発言の編集・削除、参加している議論の一覧、スパム対策（#35）も難しくなる。
- 入力を未ログインで始められ、表示をニックネームにできれば、投稿のハードルは低く保てる。

## Alternatives

- **投稿前に、既存の同じ問い・話を確かめさせる案**：投稿の動機を下げるため採用しない。
- **明白な単純重複の投稿を抑制する案（DEC-0005 決定3の当初の形）**：何が「明白な単純重複」かを投稿時点で判断する負担があり、時期による答えの変化や新しい資料を取りこぼすため、投稿後の案内と統合に置き換える。
- **重複を許容し、統合も行わない案**：中身が分散し、質が下がるため採用しない。
- **匿名投稿を許可する案**：候補の判断材料・自分の投稿の管理・スパム対策が成り立たないため採用しない。
- **入力の開始からログインを必須とする案**：投稿のハードルが上がるため採用しない。

## Consequences

- **MVPスコープ**：7章の「明白な単純重複には既存の会話への参加を案内する」を、投稿直後の案内と投稿後の統合に改める。未ログイン時の「投稿確定時に認証を必須とするか」の未決事項を、本Decisionで解消する。
- **ドメイン設計**：重複の扱い（会話の重複は歓迎し、Discoveryの乱立は避ける）を、成立・関係の判断の記述に追加する。同じ問いの繰り返しを関心・季節性の手がかりとして扱うことを記載する。
- **画面（#67）**：投稿直後に似たDiscoveryとわかってきたことを示す表示と、その文言。未ログイン時の入力開始、確定時のログイン、ログイン後の入力内容の引き継ぎ。ニックネームの表示。
- **認証・ユーザー（S07・S08）**：ニックネームの設定と表示。
- **サービスの伝え方**：「疑問や感動を分かち合う」という考え方を、画面の言葉と、後続のLP等で一貫して伝える。
