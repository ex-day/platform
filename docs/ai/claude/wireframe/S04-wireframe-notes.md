# S04 Wireframe（Issue #18）

対象: Issue #18。基準となる定義書は `docs/ui/screens/S04-contribution-save.md`（PR #41マージ後、B案／Disclosure採用済みのmain）、`C22-location-input.md`、`C23-media-source-dialog.md`、`C24-time-period-input.md`、DEC-0002、DEC-0003。

## ファイル

- `PC-S04-New-Knowledge-Closed.png` — 新規・知識・初期表示（「場所・時期を詳しく伝える（任意）」は折りたたみ閉）。基準形。
- `PC-S04-New-Knowledge-Open.png` — 同上、折りたたみを開いた状態。場所／いつの話ですか／いつ見たり体験したりできますかの3ブロックを表示。
- `PC-S04-New-Question.png` — 投稿種別が「疑問」の場合。表示項目・折りたたみの扱いは知識と同一で、文面のみ疑問の例（浜松町の建物入口）に差し替え。
- `PC-S04-Edit-Knowledge.png` — 既存の知識を編集するケース。折りたたみを開いた状態で既存値（場所・時代・季節等）が入っていることを示す。
- `PC-S04-Unauthenticated.png` — 未ログイン状態から投稿を開始するケース。画面構成・入力項目はログイン状態と同一であることを示す。認証タイミング自体はIssue #18の前提により本Wireframeでは確定しない。
- `Mobile-S04-New-Knowledge.png` — 新規・知識のモバイル版（375px）。折りたたみ 閉→開 の2状態。
- `S04-wireframe-source.html` — 上記6枚のソースをまとめたHTML。

## 確認できたこと

- B案（本文優先＋任意詳細の折りたたみ）を採用した現行定義どおりに構成しており、表示項目・アクションを独自に追加・削除していない。
- 折りたたみの開閉は表示のみを切り替え、入力内容や選択状態を保持する（定義書のアクション「展開時に...確認・変更できるようにする」に対応）。
- 知識／疑問は投稿種別チップの選択以外、表示項目・折りたたみの扱いに差はない。
- 編集モードは新規と同じ項目を編集できる状態として表現した。投稿種別の変更可否は定義書どおり未確定のまま。
- 未ログイン状態は、認証に関する独自の仕様を追加せず、「確認へ進むまでは入力できる」ことのみを示すに留めた。

## 気づいた点（Non-blocking）

- モバイル幅（375px）だと、「場所・時期を詳しく伝える（任意）」の見出しと開閉ラベルが3行に折り返される。Mock検討時にラベルの長さ・配置を見直す余地がある。
- 未ログイン状態の画面で、ヘッダー側にログイン導線をどう表示するかは現行C01定義に無いため、今回は追加せず空欄のままにしている。認証タイミングの検討と合わせてC01側の検討も必要になる可能性がある。
- 新規×知識／新規×疑問／編集×知識／編集×疑問／PC×Mobileの全組み合わせ（8通り）はすべて個別の画像にはしていない。知識/疑問・新規/編集それぞれの差分は限定的（文面・投稿種別チップ・初期値の有無）なため、代表的な組み合わせのみを図示し、他の組み合わせは本ノートの説明で言葉として記録した。
