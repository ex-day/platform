# 機能一覧

画面・コンポーネントから呼び出される機能（F）の一覧。機能の定義は`docs/ui/functions/`に置く。IDの採番・廃止・参照のルールは[各種設計資料の作成方針](各種設計資料作成方針.md)の「画面・コンポーネント・機能のIDの採番ルール」（[DEC-0011](decisions/DEC-0011-id-numbering-rules.md)）に従う。IDは変えず、廃止したIDは再利用しない。

2026-11-15：根本整理（DEC-0019〜0023、[Issue #135](https://github.com/ex-day/platform/issues/135)）と [MVP スコープ v0.4](ex-day_mvp_scope.md) に合わせて作り直した。新しい機能（F05〜）の番号は候補であり、人が PR のレビューで確定する。既存の機能の定義ファイルは v0.3 の中身のままで、新しい機能の定義ファイルはまだない。

### F10 の後続検討：安全性に関する公開制御

2026-11-16 の人の判断（PR #145 のレビュー）。今回は原則と検討事項を記録するまでとし、具体的な判定基準・AI の利用・緊急時の対応の流れ・法的な論点は未決定とする。

- **原則**：運営は知識の正しさを裁定する存在ではなく、知識が安全に蓄積される環境を保つ存在である
- 生命・身体などに重大な危険を及ぼし得る情報は、単なる異論とは別に扱う。一方、運営に専門の知識がないことを理由に非公開が恒久化すると、知識の網羅性と品質を損ない、詳しいユーザーから知識が集まる機会も失う
- 対象の正誤・安全性を断定することと、投稿が危険な行動を誘発する可能性を評価することを区別する（例：野生のキノコの写真。運営や AI がその毒性を確実に判定できるとは限らない）
- 公開の段階として、通常公開・注意喚起付きの公開・非公開（緊急時の暫定の制限を含む）を検討する。注意喚起だけで重大な被害を防げない場合は、非公開を続けられる余地を残す
- 会話としての公開と、体験を促す Discovery としての成立・公開を区別し、後者にはより慎重な基準を設ける
