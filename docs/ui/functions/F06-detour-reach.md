# F06: detour-reach（寄り道の到達圏）

## 状態

- **番号は候補**（機能一覧）。2026-11-19 新規（[Issue #161](https://github.com/ex-day/platform/issues/161)）。**1段目（データの形と計算の決まりの案）**。人がレビューで決めたあと、2段目で OpenAPI、3段目で DB（V3）と実装を行う（S14・S15・S01 の取得用 API と同じ進め方）。2026-11-20、1段目のレビュー（PR #165）を反映した（場所と駅の間の移動を起点・終点の両側で引く、自動で選ぶ駅を15分以内に、行き方と自動の目安の選び方、経由する駅を API の約束にしない、歩きのデータは #163 で決めてから計算を作る）
- 計算の仕組みは MVP では pgRouting（[DEC-0014](../../decisions/DEC-0014-reach-engine-pgrouting-provisional.md) 決定1）。歩きのデータ・データの更新と切り戻し・性能と運用の決まりは [#163](https://github.com/ex-day/platform/issues/163) で決める。歩きのデータは、poc #23・#31 の結果で OSM が有力（N13 は細い道・参道・駅の中や駅前の道が足りず、到達点の約4割を道に結べなかった）で、#163 は pgRouting＋OSM で最終の確認をし、ODbL と運用を含めて採否を決める位置づけ。**OpenAPI（2段目）は歩きのデータに依らずに進め、計算の実装（3段目）は #163 で歩きのデータを決めてから行う**
- 寄り道の考え方は [DEC-0013](../../decisions/DEC-0013-detour-suggestion-in-mvp.md)、画面は [S12](../screens/S12-detour.md)、入口と URL は [DEC-0022](../../decisions/DEC-0022-top-page-and-detour-entry.md)。PoC は ex-day/poc の `reach/`（#5・#6・#23・#27・#31・#40・#42）

## 関連概要

起点（場所）・使える時間・終点から、寄れる場所と「そこで何分過ごせるか」を出す。S12（寄り道）、C35（TOP の小さな地図）、S02 の上位の結果の移動時間で使う。

- 時刻表を使わず、駅と路線ごとの表定速度で「だいたい○○分」を出す。誤差は「行けない」側に寄せる（DEC-0013 決定1）
- 計算の起点・終点は駅。場所を起点・終点にしたときは、その場所の計算の起点の駅から計算し、場所と駅の間の移動も引く（下の「計算の決まり 1・2」。S12「起点と計算の起点」）
- 結果は場所の単位。場所の上の Discovery・まとまり（観光・生活のエリア）は、F06 の結果に場所の情報を重ねて作る（S12）

## 想定する使い方

2026-11-20 の人とのやりとり（PR #165）。寄り道を調べる場面と、起点・終点の置き方。

- **今いるところから**（外出中に「今から寄れるところは？」）：画面の側で、現在地をいちばん近い駅の場所に置き換えてから F06 を呼ぶ（座標は送らない。DEC-0022 決定5）。起点は駅になり、場所と駅の間の移動は 0。**今いるところから駅までの歩きは計算に入らない**（座標を受けないため）。画面では「桜木町駅から」のように起点の駅を出し、歩く分は利用者が読み取れるようにする
- **行ってみたい場所（目的地）を見つけた。まだ時間が余っているけど、どうしよう？**：ex-day で駅以外の場所を起点・終点にするのは、主にこの場面
  - **目的地のあとに寄る**：起点＝目的地（例：小机城址）、終点＝帰る場所。目的地を出たら、まず駅まで歩く（小机城址 → 小机駅 約8分）
  - **目的地の前・途中に寄る**：起点＝今いる駅、終点＝目的地（「別の場所に着く」）。最後に駅から目的地まで歩く
  - どちらも、目的地と駅の間の歩きは実際に必ずかかる時間なので、**起点側・終点側の両方で引く**（計算の決まり 1・2）。引かないと「寄れる」と出たのに間に合わない、が起きる
- **目的地が2つ以上**（「小机城址ともう1か所は決めてある。その間と前後で寄れるところは？」）：経由地を固定する寄り道になり、MVP の F06（起点・使える時間・終点）では表せない。MVP では、目的地を1つずつ起点か終点に置いて調べてもらう。将来、寄り道で見つけた場所を「候補地」にし、経由地にしてほかに寄れるところを探す機能の候補とする（[#166](https://github.com/ex-day/platform/issues/166)。MVP では扱わない）

## 入力

| 項目 | 内容 |
|---|---|
| 起点 | 場所の識別子（駅の場所、または駅以外の場所）。座標は受けない（DEC-0022 決定5。現在地は画面の側で最寄りの駅の場所に置き換える） |
| 使える時間 | 分。30〜480分・15分刻み（S12） |
| 終点 | 往復（既定）／片道（終点なし）／別の場所（場所の識別子） |

## 出力（概要。形は2段目の OpenAPI で決める）

- 起点・終点の表示の場所と、計算の起点・終点の駅（違うときは両方。「小机城址（小机駅から）」）と、場所と駅の間の移動の分数
- 寄り道をしないで終点に着く時間（往復・片道は 0、帰り道は起点の場所 → 終点の場所。場所と駅の間の移動を含む）。使える時間がこれより短ければ、寄れる場所はない
- 寄れる場所ごとに：場所、そこで何分過ごせるか、移動時間（行き・帰り）を必ず返す。利用者に見せる行き方（出発する駅または場所、手段、分数、目安かどうか）は、あるときだけ返す。**計算の中で経由した駅そのものは、API の約束にしない**（DEC-0014 決定2：駅を経由するか、場所へ直接届くかを API の外に出さない。2026-11-20、PR #165 のレビュー）
- 地図の帯：過ごせる時間の帯（15・30・60・120分以上。PoC #42）の形
- 計算できないとき：その理由（下の「計算できないとき」）

## 計算の決まり（案）

### 1. 計算の起点・終点の駅

起点・終点の場所から、計算に使う駅（駅の場所）を次の順に決める。

1. その場所が駅なら、その駅（場所と駅の間の移動は 0）
2. その場所の「行き方の代表の駅」（`place.access_station_place_id`）があれば、その駅
3. その場所の行き方（下の「データの形 2」）のうち、使える順番（DEC-0013 決定3）でいちばん上のものの駅
4. どれもなければ、自動の目安（下の 4 の 2）で**片道15分以内**に歩けるいちばん近い駅（直線ではおよそ 920m。**案**）
5. それもなければ、計算できない（下の 5。駅を直接選んでもらう）

**場所と駅の間の移動は、起点側・終点側の両方で引く**（2026-11-20、PR #165 のレビュー。以前の案の「起点から駅までは含めない」をやめた）。分数は、寄り道先の場所と駅の間と同じ決まり（下の 4）で決める。誤差を「行けない」側に寄せ、起点側と終点側で扱いをそろえるため。画面では「小机城址（小机駅から 歩き約8分）」のように、駅と分数を出す。

### 2. 駅までの時間

- **t1**：起点の場所 → 寄り道先の駅。起点の場所と計算の起点の駅の間の移動（上の 1）＋ 鉄道（表定速度）の時間 ＋ 乗るたびの待ち（**5分**。PoC #42）
- **t2**：寄り道先の駅 → 終点。
  - 往復：寄り道先の駅 → 計算の起点の駅（鉄道＋待ち）＋ 計算の起点の駅と起点の場所の間の移動
  - 帰り道：寄り道先の駅 → 計算の終点の駅（鉄道＋待ち）＋ 計算の終点の駅と終点の場所の間の移動
  - 片道：0
- 乗換は10分の固定。駅をまたいで歩く乗換はしない（PoC #5。「行けない」側）
- 寄り道先の駅が起点・終点の駅そのもの（同じ駅グループ）のときは、鉄道の時間は 0 分（場所と駅の間の移動は引く）

### 3. 場所で過ごせる時間

**場所で過ごせる時間 ＝ 使える時間 − t1 − t2 − 駅との往復の歩き（2 × 駅から場所まで）**

- 終点ごとの t2 は上のとおり（DEC-0013 決定1。2026-11-19）
- 滞在の時間は入力にしない。この時間そのものを「そこで何分過ごせるか」として返す。DEC-0013 の Deferred「到達圏の API が返す余裕の意味」は、**場所で使える時間の合計**とする（PoC #42 と同じ）
- 1つの場所に、使える駅が複数あるときは、過ごせる時間がいちばん長い駅を使う
- **寄れる時間の下限**：過ごせる時間が **15分**以上の場所だけを出す（**案**。PoC #42 の既定）

### 4. 駅と場所の間（行き方と自動の目安）

寄り道先の場所と駅の間、起点・終点の場所と計算の駅の間に、同じ決まりを使う（片道の分数）。

1. **自動の目安**：駅から、場所の到達点までの歩き
   - 歩きのデータ（道のり）は #163 で決める（OSM が有力）。道に結べない到達点の扱いも #163 で決める
   - 到達点の選び方：確かな入口があれば、確かな入口のうち駅からいちばん近いもの。なければ推定の到達点のうちいちばん近いもの。どちらもなければ代表点
   - **片道15分を超える駅と場所の組は、候補から外す**（15分に丸めない。PoC #42 と同じ）
2. **行き方があるとき**：使える順番（DEC-0013 決定3）でいちばん上の行き方の分数を使う。バスは、待ちの目安（**15分**）を足す
   - その行き方と**同じ駅グループから、同じ着く先（到達点。着く先がなければ場所の自動の目安の到達点）まで**の自動の目安が出せるときは、**長いほう**（max（行き方, 自動の目安））を使う（DEC-0013 決定3 の「大きく食い違うときは長いほう」を、閾値なしの max にした。2026-11-20、PR #165 のレビュー）。そのため、行き方があっても、比べられる組は自動の目安も計算する
   - 同じ駅グループ・同じ着く先で比べられないとき（バスの行き方など）は、行き方の分数をそのまま使う
   - 行き方の分数には、上の15分の上限を当てない（行き方は事実として扱う）
3. 画面では、行き方の分数か自動の目安かを分かるように出す

### 5. 計算できないとき

| 状態 | 返すもの |
|---|---|
| 起点・終点の場所に計算の駅が決まらない（上の 1 の 5。代表の駅・行き方がなく、15分以内に歩ける駅もない） | 計算できない理由と、駅を直接選ぶ案内（S12） |
| 使える時間が、寄り道をしないで終点に着く時間より短い（帰り道） | 寄れる場所はない、と、寄り道をしないで着く時間 |
| 寄れる場所が0件 | 0件（帯も空） |

事前計算のデータが作り直しに失敗したときの扱い、応答時間・同時実行の上限は #163 で決める。

### 6. 設定で持つ値

計算の決まりの値は、データ（行き方）に書き込まず、設定（アプリの設定ファイル）で持ち、あとから変えられるようにする（DEC-0013 決定3 のバスの待ちと同じ考え方）。

| 値 | 既定（**案**） | 出どころ |
|---|---|---|
| 乗るたびの待ち | 5分 | PoC #42 |
| 乗換 | 10分 | PoC #5 |
| バスの待ちの目安 | 15分 | DEC-0013 決定3 |
| 歩きの速さ | 80m/分 | PoC #23・#42（遠回りの係数 1.3 は、道のりの代わりに直線で測るときだけ。使うかは #163） |
| 自動の歩きの上限（片道） | 15分 | PoC #42 |
| 計算の駅を自動で選ぶ範囲 | 自動の歩きの上限と同じ（15分） | 2026-11-20、PR #165 のレビュー（以前の案は直線 2km） |
| 寄れる時間の下限 | 15分 | PoC #42 |
| 地図の帯 | 15・30・60・120分以上 | PoC #42 |

## データの形（案。DB V3 で作る）

DB V2 のどの表に足すか・新しく作るかの案。表の名前・列は3段目（DB V3 のマイグレーション）で確定する。到達圏の計算のデータ（下の 1・5・6）は、ドメインの表と分けて `reach` のスキーマに置く（運用・実装のデータ。論理設計 14節）。

### 1. 駅（DEC-0013 決定4）

- **利用者から見える駅は場所**（`place`。種類が「駅」）。**1つの駅の場所＝ N02 の駅グループ（乗換できるまとまり）1つ**とする（例：桜木町駅の場所は JR・横浜市営地下鉄の桜木町をまとめたもの）
- **計算の中の駅**：`reach.station`（station_id。路線ごとの駅 1行。N02 の路線・駅名・ホームの位置）。`place_id`（駅の場所）を持つ
- **N02 の年度ごとの対応**：`reach.station_source`（station_id・年度・N02 の駅コード・グループコード）。年度が変わって駅コードが変わっても、station_id と駅の場所は変えない。名寄せの運用（新しい駅・廃止・名前の変更）は #163 のデータの更新の手順で決める

### 2. 行き方（DEC-0013 決定2）

`place_access`（新しい表）：1つの場所に何件でも。

| 列 | 内容 |
|---|---|
| 場所 | 行き方の先の場所 |
| 駅 | 駅の場所（`place`） |
| 主な手段 | 徒歩／バス／タクシー／その他 |
| 合計の分数 | 駅を出てから着く先まで |
| 着く先 | 到達点（下の 3）。なければ場所そのもの |
| 元の書き方・ひとこと | 任意 |
| 出どころ | 運営／公式／ユーザー／会話／自動計算 |
| 確かめた状態 | 人が確かめた／機械で取り出した・未確認 |
| 出典の URL・取得日・確かめた日 | |
| 状態 | 有効／無効（古い・誤り）／取り出しの失敗 |
| 登録したもの | 人（ユーザー・運営）、または取得の処理。判断の記録（`decision`）を持つ |

- 直さずに足していく（DEC-0013 決定2）。人が登録したものは AI の解釈で書き換えない
- **行き方の代表の駅**（`place.access_station_place_id`）は残し、計算の起点の駅（計算の決まり 1 の 2）に使う。行き方が増えても、代表の駅は人（運営）か取り込みの処理が決める。行き方から自動で書き換えない（**案**）
- MVP では、利用者が行き方を登録する画面は作らない（DEC-0013 決定2 の「MVP で決めないこと」のまま）。最初の行き方は、運営の登録（#57）と取り込みで入れる

### 3. 到達点（DEC-0013 決定5）

`place_arrival_point`（新しい表）：1つの場所に0以上。

| 列 | 内容 |
|---|---|
| 場所 | |
| 位置 | 点（SRID 4326） |
| 種類 | 確かな入口／推定の到達点 |
| 手段 | 徒歩（MVP）。将来：車（駐車場）・バス（停留所） |
| 出どころ | OSM の入口の印／OSM の道と範囲の境界の交わり・範囲の端（推定）／公式／運営 |

### 4. 場所の位置（DEC-0013 決定5）

- **範囲**は今の `place.geom` のまま（AREA は Polygon・MultiPolygon。V2 で受けられる）
- **代表点**は列を足さず、形から決める（地点はその点、エリアは面の上の1点、経路は始点。S15・S01 と同じ）。地図に出す位置を人が直したいときに列を足す（**案**）
- **もとにした OSM の ID（複数）**：`place_osm_ref`（場所・OSM の種類と ID）。OSM を DB に持つときの ODbL の扱い（#163）を決めてから作る

### 5. 鉄道のグラフ（到達圏の事前計算）

`reach.line`（路線・表定速度）、`reach.speed_override`（区間ごとの速さ）、`reach.node`・`reach.edge`（pgRouting が読むグラフ）。PoC の `reach/sql/01_schema.sql` の形を引き継ぐ。

- **作った版（build）を持つ**：`reach.build`（版・元のデータの版・作った時点・状態）。グラフと下の 6 は版ごとに持ち、使う版を1つにする。作り直しに失敗したときに前の版で続けられるようにする（手順は #163）

### 6. 駅から場所への歩き（事前計算）

`reach.place_walk`（版・駅・到達点・場所・分・計算のしかた）。

- 駅から到達点までの歩きの道のりを、前もって計算して持つ（PoC #23 の `station_spot_walk`。片道15分まで）。歩きのデータ（OSM が有力）は #163 で決める
- 起点・終点の場所と駅の間（計算の決まり 1・2）も、この表から引く

### 7. 計算の決まりの値

上の「設定で持つ値」はアプリの設定で持ち、DB には持たない。

## 決めたいこと（1段目のレビュー）

2026-11-20、PR #165 のレビューで次を決めた。

- 起点側の移動も引く（「想定する使い方」の2つの場面に合わせる。2026-11-20 の人の判断）

- 15分の下限、設定で持つ値、駅グループ＝駅の場所、代表の駅を行き方から自動で書き換えない、代表点を形から決める、グラフを版ごとに持つ、MVP で利用者が行き方を登録する画面を作らない：この案で進める
- 駅以外の終点・起点の、場所と駅の間の移動を引く（計算の決まり 1・2）
- 計算の駅を自動で選ぶのは、片道15分以内に歩ける駅に限る（以前の案の直線 2km をやめた）
- 行き方と自動の目安は、比べられる組は max（計算の決まり 4）。自動の歩きの15分は、超える組を外す意味
- 寄れる場所ごとの経由した駅は API の約束にせず、利用者に見せる行き方を任意で返す（出力）
- 歩きのデータは #163 で決め、計算の実装はそのあと（状態）

残り（2段目のレビューで見る）：

1. 片道15分以内の駅がない起点（郊外の場所など）を、計算できないとするか

MVP では扱わないこと：目的地が2つ以上の寄り道（経由地を固定する。#166）
