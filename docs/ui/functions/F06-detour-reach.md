# F06: detour-reach（寄り道の到達圏）

## 状態

- **番号は候補**（機能一覧）。2026-11-19 新規（[Issue #161](https://github.com/ex-day/platform/issues/161)）。**1段目（データの形と計算の決まりの案）**。人がレビューで決めたあと、2段目で OpenAPI、3段目で DB（V3）と実装を行う（S14・S15・S01 の取得用 API と同じ進め方）
- 2026-11-20、1段目のレビュー（PR #165）を反映した。**利用者が移動を始める駅（と帰り道の到着の駅）を選び、F06 はその駅から先を、鉄道と徒歩で計算する**（人の判断）。場所から駅を自動で決める規則と、場所と駅の間の移動を引く案はやめた。**MVP ではバスを扱わない**（人の判断）
- 計算の仕組みは MVP では pgRouting（[DEC-0014](../../decisions/DEC-0014-reach-engine-pgrouting-provisional.md) 決定1）。歩きのデータ・データの更新と切り戻し・性能と運用の決まりは [#163](https://github.com/ex-day/platform/issues/163) で決める。**歩きのデータは OSM の歩ける道にした**（2026-11-21、人の判断。poc #46 で pgRouting＋N13 と pgRouting＋OSM を同じ条件で比べた。DEC-0014 決定1）。**OpenAPI（2段目）は歩きのデータに依らずに進め、計算の実装（3段目）は歩きのデータを決めてから行う**
- 寄り道の考え方は [DEC-0013](../../decisions/DEC-0013-detour-suggestion-in-mvp.md)、画面は [S12](../screens/S12-detour.md)、入口と URL は [DEC-0022](../../decisions/DEC-0022-top-page-and-detour-entry.md)。PoC は ex-day/poc の `reach/`（#5・#6・#23・#27・#31・#40・#42）

## 関連概要

利用者が選んだ移動を始める駅・使える時間・終点から、寄れる場所と「そこで何分過ごせるか」を出す。S12（寄り道）、C35（TOP の小さな地図）、S02 の上位の結果の移動時間で使う。

- **MVP の F06 の責務は「選んだ駅から、鉄道と徒歩で寄れる場所と、過ごせる時間を出す」**（2026-11-20）
- 時刻表を使わず、駅と路線ごとの表定速度で「だいたい○○分」を出す。誤差は「行けない」側に寄せる（DEC-0013 決定1）
- 計算の起点・終点は、利用者が選んだ駅。現在地・選んだ場所からその駅までの移動は、F06 に含めない（使える時間は「選んだ駅に着いた時点」から数える）
- 結果は場所の単位。場所の上の Discovery・まとまり（観光・生活のエリア）は、F06 の結果に場所の情報を重ねて作る（S12）

## 想定する使い方

2026-11-20 の人とのやりとり（PR #165）。

- **今いるところから**（外出中に「今から寄れるところは？」）：画面が、現在地のまわりの駅を候補として数件出し、利用者が移動を始める駅を選ぶ
- **行ってみたい場所（目的地）を見つけた。まだ時間が余っているけど、どうしよう？**：ex-day で駅以外の場所から寄り道を調べるのは、主にこの場面
  - **目的地のあとに寄る**：目的地（例：小机城址）のまわりの駅を候補として出し、利用者が移動を始める駅を選ぶ。終点は帰る駅
  - **目的地の前・途中に寄る**：今いる駅から始め、終わり方を「別の駅へ向かう」にして、到着の駅として目的地のまわりの駅を利用者が選ぶ
- **駅を利用者に選んでもらう理由**：駅から離れた場所では、徒歩より、バスや車で別の駅へ出る人も多い。「綱島・鶴見・新横浜のどれを使うか」は、直線の距離だけでは決められず、バスの本数・渋滞・行き先にも左右される。MVP ではバスのデータを持たない（下）ので、サービスの側で推定するより、利用者に選んでもらうほうが正確で、F06 の範囲もはっきりする（2026-11-20 の人の判断）
- 画面には「新横浜駅から計算します。現在地・選んだ場所から新横浜駅までの移動時間は含みません」のように出す（S12）
- **目的地が2つ以上**（「小机城址ともう1か所は決めてある。その間と前後で寄れるところは？」）：経由地を固定する寄り道になり、MVP の F06 では表せない。MVP では、目的地を1つずつ、移動を始める駅か到着の駅のまわりとして調べてもらう。将来、寄り道で見つけた場所を「候補地」にし、経由地にしてほかに寄れるところを探す機能の候補とする（[#166](https://github.com/ex-day/platform/issues/166)。MVP では扱わない）

## 入力

| 項目 | 内容 |
|---|---|
| 移動を始める駅（`from`） | **必須**。駅の場所の識別子（利用者が選んだもの）。座標は受けない（DEC-0022 決定5） |
| 使える時間 | 分。30〜480分・15分刻み（S12）。選んだ駅に着いた時点から数える |
| 終わり方（`to`） | 3択（2026-11-20 の人の判断）：**移動を始める駅へ戻る**（既定。`to` を省く）／**寄り道先で終わる**（`to=none`）／**別の駅へ向かう**（`to=<到着の駅>`）。到着の駅は「別の駅へ向かう」のときだけ必須 |

### 駅の選び方（画面の補助。F06 の外）

まわりの駅は、F06 の入力の決まり・制約ではなく、**駅を選ぶための画面の補助**（2026-11-20 の人の判断）。

- **移動を始める駅**：現在地や場所のページから入ったときは、そのまわりの駅を候補として数件、距離の順に出す。距離の順は候補の表示だけに使い、自動で決めたり「おすすめ」としたりはしない（F06 の正解の判定ではない）。候補にない駅は駅の名前で探せる。最近選んだ駅を上に出してよい（MVP では端末の中の履歴でよい）
- **到着の駅**（「別の駅へ向かう」を選んだときだけ）：現在地や出発地のまわりとは限らない
  - 帰着する場所の文脈があるとき（目的地の前・途中に寄る等）：その場所のまわりの駅を候補に出してよい
  - 帰着する場所がないとき：最近選んだ駅と、駅の名前での検索を使う
  - 「別の駅へ向かう」を選んだだけのとき：駅の名前での検索を基本にし、現在地のまわりの駅は出さない
- 画面では、`to` が空の未入力の状態として見せず、既定で「○○駅へ戻る」が選ばれた状態にする（S12）
- 駅の候補・名前での検索の API の形（現在地のまわりの駅は、座標を URL に出さずに求める）は、2段目（OpenAPI）で決める

## 出力（概要。形は2段目の OpenAPI で決める）

- 移動を始める駅・到着の駅
- 寄り道をしないで終点に着く時間（往復・片道は 0、帰り道は移動を始める駅 → 到着の駅）。使える時間がこれより短ければ、寄れる場所はない
- 寄れる場所ごとに：場所、そこで何分過ごせるか、移動時間（行き・帰り）を必ず返す。利用者に見せる行き方（駅、徒歩、分数、目安かどうか）は、あるときだけ返す。**計算の中で経由した駅そのものは、API の約束にしない**（DEC-0014 決定2：駅を経由するか、場所へ直接届くかを API の外に出さない。2026-11-20、PR #165 のレビュー）
- 地図の帯：過ごせる時間の帯（15・30・60・120分以上。PoC #42）の形。寄れる場所からではなく到達圏の全体から作る
- 寄れる場所は、過ごせる時間の長い順にページで返し、カーソルで最後まで読める（全体を件数で打ち切らない。2段目のレビュー）
- 計算できないとき：その理由（下の「計算できないとき」）

## 計算の決まり（案）

### 1. 計算する範囲

- 移動を始める駅から寄り道先まで（鉄道＋寄り道先の駅と場所の間の徒歩）
- 寄り道先で過ごせる時間
- 往復・帰り道は、寄り道先から、移動を始める駅または到着の駅まで
- 寄り道先の駅と場所の間は、徒歩の時間を往復分引く
- **含めないもの**：現在地・選んだ場所から移動を始める駅まで、到着の駅から先。場所から駅を自動で決めることもしない（以前の案の「駅 → 代表の駅 → 行き方 → 徒歩15分以内の駅」は、起点・終点には使わない。2026-11-20）
- **バスでしか行きにくい寄り道先は、MVP では出さない**（駅から徒歩15分以内の場所だけ。下の 4）

### 2. 駅までの時間

- **t1**：移動を始める駅 → 寄り道先の駅。鉄道（表定速度）の時間 ＋ 乗るたびの待ち（**5分**。PoC #42）
- **t2**：寄り道先の駅 → 終点の駅（往復は移動を始める駅、帰り道は到着の駅。鉄道＋待ち）。片道は 0
- 乗換は10分の固定。駅をまたいで歩く乗換はしない（PoC #5。「行けない」側）
- 寄り道先の駅が、移動を始める駅・到着の駅そのもの（同じ駅グループ）のときは 0 分

### 3. 場所で過ごせる時間

**場所で過ごせる時間 ＝ 使える時間 − t1 − t2 − 駅との往復の歩き（2 × 駅から場所まで）**

- 終点ごとの t2 は上のとおり（DEC-0013 決定1。2026-11-19）
- 滞在の時間は入力にしない。この時間そのものを「そこで何分過ごせるか」として返す。DEC-0013 の Deferred「到達圏の API が返す余裕の意味」は、**場所で使える時間の合計**とする（PoC #42 と同じ）
- 1つの寄り道先に、徒歩で使える駅が複数あるときは、旅程の全体で過ごせる時間がいちばん長くなる駅を、計算の中で選ぶ（どの駅を選んだかは API の約束にしない）
- **寄れる時間の下限**：過ごせる時間が **15分**以上の場所だけを出す（**案**。PoC #42 の既定）

### 4. 寄り道先の駅と場所の間（徒歩）

MVP では徒歩だけを扱う（バスは扱わない。下の「MVP では扱わないこと」）。

1. **自動の目安**：駅から、場所の到達点までの歩き
   - 歩きのデータ（道のり）は OSM の歩ける道（DEC-0014 決定1）。つながっていない小さな島（点が100未満）は除いてから結ぶ。**道に結べない到達点は外す**（直線×1.3 で代わりに測らない。行き方があればそちらを使う）
   - 到達点の選び方：確かな入口があれば、確かな入口のうち駅からいちばん近いもの。なければ推定の到達点のうちいちばん近いもの。どちらもなければ代表点
   - **片道15分を超える駅と場所の組は、候補から外す**（15分に丸めない。PoC #42 と同じ）
2. **徒歩の行き方があるとき**：使える順番（DEC-0013 決定3）でいちばん上の、徒歩の行き方の分数を使う
   - その行き方と**同じ駅グループから、同じ着く先（到達点。着く先がなければ場所の自動の目安の到達点）まで**の自動の目安が出せるときは、**長いほう**（max（行き方, 自動の目安））を使う（DEC-0013 決定3 の「大きく食い違うときは長いほう」を、閾値なしの max にした。2026-11-20、PR #165 のレビュー）。そのため、行き方があっても、比べられる組は自動の目安も計算する
   - 比べられないとき（自動の目安が出せない到達点など）は、行き方の分数をそのまま使う
   - 徒歩の行き方でも、片道15分を超えるものは、MVP では寄り道先の候補にしない（上の 1 と同じ範囲にそろえる）
   - **バス・タクシー等の行き方は、MVP の F06 では参照しない**
3. 画面では、行き方の分数か自動の目安かを分かるように出す

### 5. 計算できないとき

| 状態 | 返すもの |
|---|---|
| 移動を始める駅・到着の駅が駅の場所でない、またはない | 入力の誤り（駅を選び直す） |
| 使える時間が、寄り道をしないで終点に着く時間より短い（帰り道） | 寄れる場所はない、と、寄り道をしないで着く時間 |
| 寄れる場所が0件 | 0件（帯も空） |

事前計算のデータが作り直しに失敗したときの扱い、応答時間・同時実行の上限は #163 で決める。

### 6. 設定で持つ値

計算の決まりの値は、データ（行き方）に書き込まず、設定（アプリの設定ファイル）で持ち、あとから変えられるようにする（DEC-0013 決定3 の考え方）。

| 値 | 既定（**案**） | 出どころ |
|---|---|---|
| 乗るたびの待ち | 5分 | PoC #42 |
| 乗換 | 10分 | PoC #5 |
| 歩きの速さ | 80m/分 | PoC #23・#42（道に結べない到達点は外すので、直線×1.3 は使わない） |
| 自動の歩きの上限（片道） | 15分 | PoC #42 |
| 寄れる時間の下限 | 15分 | PoC #42 |
| 地図の帯 | 15・30・60・120分以上 | PoC #42 |

## データの形（案。DB V3 で作る）

DB V2 のどの表に足すか・新しく作るかの案。表の名前・列は3段目（DB V3 のマイグレーション）で確定する。

**3段目で作ったもの**（2026-11-21）：1〜3 を `db/migration/V3__add_station_and_place_access.sql` で作った（`reach.line`・`reach.station`・`reach.station_source`・`place_access`・`place_arrival_point`）。路線は `reach.line`（事業者・路線の名前）に分け、`reach.station` から指す。行き方は判断の記録（`created_decision_id`）を必ず持ち、登録したのが人か取得の処理かは判断の記録の主体で分ける。駅を指す列（`reach.station.place_id`・`place_access.station_place_id`）は種類が「駅」の場所だけを DB で受け付ける（制約のトリガー）。行き方の分数は0以上（駅直結・駅構内は0分。API の `DetourAccess.minutes` と同じ）（PR #165 のレビュー）。路線の一部の廃止の扱い（`reach.station` に有効かどうかを持つか）は #163。5〜7（グラフ・版・歩き）は #163 のあとの次のマイグレーションで作る。到達圏の計算のデータ（下の 1・5・6）は、ドメインの表と分けて `reach` のスキーマに置く（運用・実装のデータ。論理設計 14節）。

### 1. 駅（DEC-0013 決定4）

- **利用者から見える駅は場所**（`place`。種類が「駅」）。**1つの駅の場所＝ N02 の駅グループ（乗換できるまとまり）1つ**とする（例：桜木町駅の場所は JR・横浜市営地下鉄の桜木町をまとめたもの）
- **計算の中の駅**：`reach.station`（station_id。路線ごとの駅 1行。N02 の路線・駅名・ホームの位置）。`place_id`（駅の場所）を持つ
- **N02 の年度ごとの対応**：`reach.station_source`（station_id・年度・N02 の駅コード・グループコード）。年度が変わって駅コードが変わっても、station_id と駅の場所は変えない。名寄せの運用（新しい駅・廃止・名前の変更）は #163 のデータの更新の手順で決める

### 2. 行き方（DEC-0013 決定2）

`place_access`（新しい表）：1つの場所に何件でも。

| 列 | 内容 |
|---|---|
| 場所 | 行き方の先の場所 |
| 駅 | 駅の場所（`place`） |
| 主な手段 | 徒歩／バス／タクシー／その他（データの形は将来の手段も持てるようにする。**MVP の F06 は徒歩だけを参照する**） |
| 合計の分数 | 駅を出てから着く先まで |
| 着く先 | 到達点（下の 3）。なければ場所そのもの |
| 元の書き方・ひとこと | 任意 |
| 出どころ | 運営／公式／ユーザー／会話／自動計算 |
| 確かめた状態 | 人が確かめた／機械で取り出した・未確認 |
| 出典の URL・取得日・確かめた日 | |
| 状態 | 有効／無効（古い・誤り）／取り出しの失敗 |
| 登録したもの | 人（ユーザー・運営）、または取得の処理。判断の記録（`decision`）を持つ |

- 直さずに足していく（DEC-0013 決定2）。人が登録したものは AI の解釈で書き換えない
- **行き方の代表の駅**（`place.access_station_place_id`）は残す。**F06 の計算には使わない**（移動を始める駅は利用者が選ぶ。2026-11-20）。S13（場所のページ）の行き方の表示に使う。行き方が増えても、代表の駅は人（運営）か取り込みの処理が決め、行き方から自動で書き換えない（**案**）
- MVP では、利用者が行き方を登録する画面は作らない（DEC-0013 決定2 の「MVP で決めないこと」のまま）。最初の行き方は、運営の登録（#57）と取り込みで入れる

### 3. 到達点（DEC-0013 決定5）

`place_arrival_point`（新しい表）：1つの場所に0以上。

| 列 | 内容 |
|---|---|
| 場所 | |
| 位置 | 点（SRID 4326） |
| 種類 | 確かな入口／推定の到達点 |
| 手段 | 徒歩（MVP）。将来：車（駐車場）・バス（停留所） |
| 出どころ | OSM の入口の印／OSM の道と範囲の境界の交わり・範囲の端（推定）／公式／運営 |

### 4. 場所の位置（DEC-0013 決定5）

- **範囲**は今の `place.geom` のまま（AREA は Polygon・MultiPolygon。V2 で受けられる）
- **代表点**は列を足さず、形から決める（地点はその点、エリアは面の上の1点、経路は始点。S15・S01 と同じ）。地図に出す位置を人が直したいときに列を足す（**案**）
- **もとにした OSM の ID（複数）**：`place_osm_ref`（場所・OSM の種類と ID）。ODbL の扱いは DEC-0014 決定1（サービスの中で使い、データベースは配らない。画面に「© OpenStreetMap contributors」）

### 5. 鉄道のグラフ（到達圏の事前計算）

`reach.line`（路線・表定速度）、`reach.speed_override`（区間ごとの速さ）、`reach.node`・`reach.edge`（pgRouting が読むグラフ）。PoC の `reach/sql/01_schema.sql` の形を引き継ぐ。

- **作った版（build）を持つ**：`reach.build`（版・元のデータの版・作った時点・状態）。グラフと下の 6 は版ごとに持ち、使う版を1つにする。作り直しに失敗したときに前の版で続けられるようにする（手順は #163）

### 6. 駅から場所への歩き（事前計算）

`reach.place_walk`（版・駅・到達点・場所・分・計算のしかた）。

- 駅から到達点までの歩きの道のりを、前もって計算して持つ（PoC #23 の `station_spot_walk`。片道15分まで）。歩きのデータは OSM の歩ける道。駅の代表点はホームの重心のまま（DEC-0014 決定1）

### 7. 計算の決まりの値

上の「設定で持つ値」はアプリの設定で持ち、DB には持たない。

## 決めたこと・残り（1段目のレビュー）

2026-11-20、PR #165 のレビューと人の判断で次を決めた。

- 15分の下限、設定で持つ値、駅グループ＝駅の場所、代表の駅を行き方から自動で書き換えない、代表点を形から決める、グラフを版ごとに持つ、MVP で利用者が行き方を登録する画面を作らない：この案で進める
- **入力の基本形**：移動を始める駅（`from`）は必須、終わり方は3択（戻る（既定）／寄り道先で終わる／別の駅へ向かう）、到着の駅（`to`）は「別の駅へ向かう」のときだけ必須。まわりの駅は駅を選ぶための画面の補助で、到着の駅は帰着する場所の文脈があるときだけまわりの駅を出し、ほかは駅の名前での検索と履歴（2026-11-20 の人の判断）
- **利用者が移動を始める駅（帰り道は到着の駅も）を選び、F06 はその駅から先を計算する**。現在地・選んだ場所からその駅までの移動は含めない。場所から駅を自動で決める規則は使わない（以前の案の「代表の駅 → 行き方 → 徒歩15分以内の駅」と、場所と駅の間の移動を引く案はやめた）
- 画面は、現在地・選んだ場所のまわりの駅を距離の順に数件出し、駅の名前でも探せ、最近選んだ駅を上に出す。自動の確定・おすすめはしない
- **MVP ではバスを扱わない**。寄り道先は駅から徒歩15分以内の場所だけ。バスの待ちの目安（15分）を設定から外し、バスの行き方を F06 は参照しない
- 行き方と自動の目安は、比べられる組は max（計算の決まり 4）。自動の歩きの15分は、超える組を外す意味
- 寄れる場所ごとの経由した駅は API の約束にせず、利用者に見せる行き方を任意で返す（出力）
- 歩きのデータは OSM にした（2026-11-21）。計算の実装（グラフ・版・歩き・到達圏の API）は、この PR の3段目の続きで行う

## 2段目（OpenAPI）で決めた形（案）

2026-11-20、PR #165。約束事は `docs/api/openapi.yaml`（タグ F06）。

- **`GET /detour/reach?from=&t=&to=&limit=`**（`getDetourReach`）：F06 の結果だけを返す。S12 の寄り道先のまとまり・場所の上の Discovery は、この結果に場所の情報を重ねて作り、S12 の取得用 API の段で決める（F06 の約束を S12 の見せ方から分けておく）
  - `from`：必須。駅でない場所は 400、ない場所は 404。`t`：30〜480・15の倍数。`to`：省略／`none`／駅の識別子
  - 応答は `kind` で判別：`reachable`（条件、寄り道をしないで着く時間、地図の帯、寄れる場所の最初のページ）／`not_enough_time`（別の駅へ向かうときに時間が足りない）
  - 寄れる場所：場所・種類・地図に出す代表点・過ごせる時間・行き（移動を始める駅から）・帰り（終わりまで）。利用者に見せる行き方（駅・徒歩・分・目安か）は任意。経由した駅は返さない
  - 並びは過ごせる時間の長い順、同じなら場所の識別子の順（全順序）。S12 の並べ方の種類は S12 の段
- **`GET /detour/reach/places?from=&t=&to=&after=&limit=`**（`getDetourReachPlaces`）：寄れる場所の続き（下の「ページとカーソル」）
- **駅の選び方（画面の補助）**：
  - `GET /stations?q=`（`searchStations`）：駅の名前で探す。同じ名前 → 前方一致 → 部分一致の順、「駅」は付けても付けなくてもよい。同じ名前の駅を見分けるために路線（事業者・路線名）を返す
  - `GET /places/{placeId}/nearby-stations`（`getPlaceNearbyStations`）：場所のまわりの駅（直線 5km 以内、距離の順、既定 5件）。場所が駅ならその駅を先頭に
  - `POST /stations/nearby`（`findStationsNearLocation`）：現在地のまわりの駅。**座標を URL に出さないため本文で受け**、保存せず、ログに本文を残さない（DEC-0022 決定5）
  - 距離は候補の表示の補助で、歩きの時間ではない。自動で決めたり「おすすめ」としたりしない
- 最近選んだ駅は画面の側（端末の中）で持ち、API は持たない

### ページとカーソル（2段目のレビュー、2026-11-20）

最初の形（既定300件・最大500件と `hasMore`）では、上限より後の場所を読めず、一度に返す量も多かった。PR #165 のレビューと人の判断で次の形にした。

- **最初の応答**（`getDetourReach`）は、条件・寄り道をしないで着く時間・地図の帯と、寄れる場所の最初のページを返す。**続き**（`getDetourReachPlaces`）は場所のページだけを返す。帯と条件はページで変わらず、帯の計算を毎回しないため、最初の応答だけで返す
- **1ページは既定20件・最大50件**（既存の一覧と同じ）。1ページの上限だけを持ち、寄れる場所の全体を件数で打ち切らない。全体の数は返さない。続きは `nextCursor` の有無で表す
- **地図の旗は今のページの場所だけに立てる**（ためていくと、データが増えたときに地図が旗だらけになるため。人の判断）。地図に出す数はページの件数で調整する。前のページへは、画面が読んだページのカーソルを覚えて読み直す（API は「前へ」を持たない）
- **帯は寄れる場所から作らず、到達圏の全体からサーバーで作る**。読み進めても変わらない。クライアントで駅の時間から作る形は、経由する駅を API の約束にすることになり（DEC-0014 決定2）、計算の決まりも画面と二重になるため採らない（人の判断）
- **カーソル**は、到達圏データの版・計算の決まりの値・条件（from・t・to）・並びのキー（過ごせる時間・場所の識別子）を含む不透明な値。条件が違う、または読んでいる間に版や計算の決まりの値が切り替わっていたら 400 とし、画面は最初から読み直す（既存の一覧と同じ扱い）。読み取りのレプリカを使うと、版の切り替えの直後にレプリカの間で版が揃わないことがあるが、同じく最初から読み直せばよい
- **ページごとの再計算**：並びのキーの「過ごせる時間」は入力ごとの計算値なので、前もって索引で並びを持てない。続きのページごとに DB の中で同じ計算と並べ替えをやり直す。その時間と、計算の結果をしばらく取っておくかは #163 の性能の確認で決める
- **まずの作り方**（人の判断、2026-11-20）：場所を主表にした SQL 1本（着ける駅と時間 → 場所と駅の歩き → 場所ごとに一番よい駅 → 過ごせる時間の順にページ分）で作る。駅ごとに上位を取ってまとめる形（駅ごとの徒歩の短い順の索引と LATERAL で、読む量を「着ける駅 × 1ページ」にする）は、#163 の性能の確認で遅かったときの改善として後で考える。API の形はどちらでも変わらない
- **S12 の寄り道先のまとまり**（「○○のあたり　そこで約90分」、中の場所・発見の数）は、読んだページからは作れない。S12 の取得用 API で到達圏の全部から集計する
- ページの間で場所が統合されると、同じ場所が重ねて出ることがある。画面は場所の識別子で重複を除く
- 一覧・検索の API 全体の原則（続きを読める一覧と、少数だけ返す枠を分ける）による既存の API の棚卸しは [#167](https://github.com/ex-day/platform/issues/167)

## MVP では扱わないこと

- **バス**（2026-11-20 の人の判断）：路線・停留所・時刻表だけでなく、頻繁な経路・系統の変更を追うデータの運用が要るため、軽い補助としても入れない。データの取得・更新・廃止や経路の変更への追従を含め、改めて判断する。`place_access` の手段にはバス等を持てる形を残すが、MVP の F06 は参照しない。DEC-0014 決定3 の「バスを入れる段では計算の仕組みを考え直す」も、そのときに合わせて判断する
- 目的地が2つ以上の寄り道（経由地を固定する。#166）
- 駅を自動で決めること（現在地・場所から、最寄りの駅を F06 の側で決める）
