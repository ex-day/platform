# F04: tag-suggest（タグの補完）

## 状態
- **番号・機能の分け方は候補**。Issue #67のPRでAIが提案し、人間がレビューで確定する（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

## 関連概要
Postの入力欄で、本文と同じ欄にタグ（「#」で始まる語）を付けやすくし、付けたタグを入力欄の中で見分けられるようにする（[DEC-0009](../../decisions/DEC-0009-conversation-understanding-and-tags.md) 決定10、Issue #67「判断：タグのMVPでの扱い」「[判断：タグの入力と表示（チップを廃止し、本文中の#タグを強調する）](https://github.com/ex-day/platform/issues/67#issuecomment-5826926978)」）。入力中にAIによる解析は行わず、ex-dayに保管されているタグとの照合だけで行う（[DEC-0003](../../decisions/DEC-0003-s04-s11-ai-analysis-boundary.md)：入力中の自動のAI対話を標準にしない）。

表示するタグは、**ユーザーが自分で「#」を付けた言葉だけ**とする。原則として、**入力したときの見た目と、投稿後の見た目をそろえる。**

## 使う場所
- [C27（新しい話を始める）](../components/C27-post-new.md)の入力欄
- [C26（みんなの声）](../components/C26-post-thread.md)の入力欄（C27と同じ入力部品を使い、同じ扱いにする）
- #タグの判定と見た目は、投稿後の表示（C26の声の本文、C27の投稿直後の案内）でも共有する

## アクション
- 「#」のあとの補完
  - 「#」に続けて入力された文字に前方一致するタグを、ex-dayに保管されているすべてのタグから、よく使われている順に返す。選ぶと本文中に「#タグ」として入る
- 入力欄の中の#タグの強調表示
  - 本文中の「#」で始まる語を、入力中から強調して表示する（色・太さ）
  - 方式は、textareaの後ろに同じ文字を持つ表示用の層を重ね、#タグの部分だけ色を付ける（textareaの文字色は透明にし、キャレットは表示する）。contenteditableやエディタのライブラリはMVPでは使わない
  - #タグの判定（区切りの規則）と見た目は、投稿後の表示と同じものを使う
- 該当するタグがない場合
  - 補完の候補は出さない。ユーザーは自分の言葉で「#」を付けてタグにできる（新しい表示するタグになる）

## MVPでは作らないもの
- 文中の言葉からのチップ（入力欄の下に「タグにする：」と候補を並べ、タップでタグにする形）：**廃止した**（Issue #67「判断：タグの入力と表示」）。入力欄の外にタグが並ぶと、本文とは別にタグを管理しているように見える。また、文中の言葉を拾ってSubject等に対応付けるのは、投稿後の解析で内部で持つタグとして行う（[F02（投稿後の会話の解析）](F02-conversation-analysis.md)）ため、同じことを入力中にユーザーへ頼む形になり役割が重なる
- 場所をもとにしたタグの候補（新規投稿では場所が確定していないため）
- 入力中のAIによるタグの候補（投稿後の解析で付く内部のタグで代わりとする。必要なら、投稿後に「このタグを付けますか？」と提案する形を後から検討する）

## 検討事項
- 立ち上げ直後の補完の辞書は、運営が登録するDiscovery（Issue #57）に付けたタグを元にする
- #タグの区切りの規則（どの記号・空白で終わるか）と、補完の表示件数の上限
- 「#」を打つ手間（特にモバイル）は補完で補う。不足する場合は、投稿後の提案を検討する
- モックでは固定のタグの一覧で表示を確認する
