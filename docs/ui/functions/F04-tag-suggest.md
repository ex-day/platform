# F04: tag-suggest（タグの補完）

## 状態
- **番号・機能の分け方は候補**。Issue #67のPRでAIが提案し、人間がレビューで確定する（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

## 関連概要
Postの入力欄で、本文と同じ欄にタグを付けやすくする（[DEC-0009](../../decisions/DEC-0009-conversation-understanding-and-tags.md) 決定10、Issue #67「タグのMVPでの扱い」）。入力中にAIによる解析は行わず、ex-dayに保管されているタグとの照合だけで行う（[DEC-0003](../../decisions/DEC-0003-s04-s11-ai-analysis-boundary.md)：入力中の自動のAI対話を標準にしない）。

## 使う場所
- [C27（新しい話を始める）](../components/C27-post-new.md)の入力欄
- [C26（みんなの声）](../components/C26-post-thread.md)の入力欄

## アクション
- 「#」のあとの補完
  - 「#」に続けて入力された文字に前方一致するタグを、ex-dayに保管されているすべてのタグから、よく使われている順に返す
- 文中の言葉からのチップ
  - 本文中の言葉のうち、既存のタグに一致するものを返す。呼び出し元は入力欄の下にチップとして表示し、タップでタグにする（「#」を打たなくても付けられる）
- 該当するタグがない場合
  - 何も返さない。ユーザーは自分の言葉で「#」を付けてタグにできる（新しい表示するタグになる）

## MVPでは作らないもの
- 場所をもとにしたタグの候補（新規投稿では場所が確定していないため）
- 入力中のAIによるタグの候補（投稿後の解析で付く内部のタグで代わりとする。[F02（投稿後の会話の解析）](F02-conversation-analysis.md)）

## 検討事項
- 立ち上げ直後の辞書は、運営が登録するDiscovery（Issue #57）に付けたタグを元にする
- 照合の方式（完全一致・表記の揺れの扱い）と、チップの表示件数の上限
- モックでは固定のタグの一覧で表示を確認する
