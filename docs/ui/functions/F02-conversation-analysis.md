# F02: conversation-analysis（投稿後の会話の解析）

## 状態
- **番号・機能の分け方は候補**。Issue #67のPRでAIが提案し、人間がレビューで確定する（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。
- 廃止した[S11（知識・疑問登録確認画面）](../screens/S11-contribution-save-confirm.md)の「解析して候補を示す」役割を、投稿後に裏で動く機能として置き換える（[DEC-0005](../../decisions/DEC-0005-contribution-thread-and-comment.md)・[DEC-0009](../../decisions/DEC-0009-conversation-understanding-and-tags.md)・[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md)）。
- 解析の構造は[DEC-0015](../../decisions/DEC-0015-conversation-analysis-claims-and-findings.md)、回し方（単位・タイミング・モデル・品質管理・予算・記録）は[DEC-0018](../../decisions/DEC-0018-f02-analysis-operations.md)、原則は[DEC-0012](../../decisions/DEC-0012-ai-conversation-analysis-principles.md)を正とする（Issue #127）。

## 関連概要
Post（声）が投稿されたあと、裏で会話を解析して、ex-dayが会話から理解しているもの（見立ての層）を作成・更新する。概念の定義は[ドメイン設計](../../ex-day_domain_model.md)2.1・3.5節を正とする（DEC-0015・DEC-0018に合わせた改訂は Issue #132）。

解析の順番は「Post → 主張 → わかってきたこと」（DEC-0015 決定1）。

- 主張（Claim、仮称）：1つのPost、または問いと答えのような数件のPostから読み取れる、自己完結した1つの主張。根拠のPostのidと、除外の状態・理由を持つ。保存するが画面には出さない（DEC-0015 決定1・2・6）
- わかってきたこと（Finding）：主張を場所・対象ごとに束ね、その場所について何がわかるかを書いたもの。説・価値。ユーザーに見せる（DEC-0015 決定4）
- 問い（OpenQuestion、仮称）：答えが付けば、わかってきたことが確かになる問い。AIが立てる。わかってきたことには含めない（DEC-0015 決定5）
- 発見の仮説（DiscoveryHypothesis）：わかってきたことを場所・対象などで束ねるときにできるもの。既存Discoveryとの突き合わせの単位（DEC-0015 決定3）
- 内部で持つタグ（TagMapping）：表示するタグの表記の揺れを吸収し、Subject等に対応付けたもの
- 提案（Proposal）：発見の仮説と既存Discoveryの突き合わせの結果（補完・新しいValueの追加・関連・派生）が基準を超えたときに、採用した構造の側へ出すもの

話題（Topic）は、必須の段にせず、いったん概念から外した（DEC-0015 決定3）。

投稿の成立は本機能の完了を待たない。本機能の未完了・失敗を理由に、成立したPostを失わせない（DEC-0005 決定7）。

## 入力
- 1段目（主張の取り出し）：新しいPost（本文、表示するタグ、Post間の参照（返信先等））と文脈。文脈は、返信の鎖（深さの上限つき。初めは8）、直前の数件（初めは5件）、器のDiscoveryの名前と場所（DEC-0018 決定1）
- 2段目（まとめ直し）：Discoveryの場所と、そのDiscoveryの有効な主張すべて（除外済みの主張は入れない。DEC-0015 決定6）
- 突き合わせ：既存のDiscovery
- 設定：段ごとのモデル・推論の設定、指示の版、文脈の範囲、除外の言葉の一覧、予算と段階の閾値（処理のたびに読む。DEC-0018 決定6）

過去の全Postを毎回送らない。主張は新しいPostの分だけ取り出し、保存した主張をまとめ直しの入力にする。

## アクション

### 標準の経路（1日1回、夜のバッチ。DEC-0018 決定1）
1. **主張の取り出し**：新しいPostの分だけ主張を取り出して保存する。確かさの言い方（「気がする」「らしい」等）を残す。除外の規則（DEC-0015 決定6）に当たる主張は、除外の状態と理由を付けて保存する
2. **まとめ直し**：新しいPostがあったDiscoveryと、根拠のPostが削除・非公開になったDiscoveryについて、有効な主張すべてから、わかってきたこと（説・価値）と問いを全体としてまとめ直す。1つのわかってきたことから作る問いは1つまで（DEC-0015 決定5）。ほかの呼び名は問いにせず、会話に出たら別名の候補として持つ（DEC-0015 決定7）
3. **前回との対応づけ**：前回のわかってきたことと、根拠の主張の重なりで対応づけ、同一性のルール（DEC-0009 決定4）に従って更新・新規・統合・分割・失効を判断する。版の履歴とReactionが付いた版を保持する
4. **結果の機械的な確かめ**：形、主張の根拠が渡した範囲にあるか、有効なわかってきたことが除外済みの主張を参照していないか。通らなければ反映せず、次のバッチでやり直す
5. **表示の前の関所**（毎回。費用によらず省かない）：新しくできた・変わったわかってきたこと・問いを、除外の言葉の一覧（AIなし）に当て、当たったものだけ上位モデルで判定する。判定が出るまで表示しない（保留）。関所が失敗したら表示しない側に倒す。Post自体は保留にしない（DEC-0018 決定3）
6. **表示に反映**：関所を通ったものをC25などに出す

### そのほかの解析
- 表示するタグの表記の揺れを吸収し、内部で持つタグとしてSubject等に対応付ける。ユーザーが書いたタグは書いたまま残す（Issue #67「タグのMVPでの扱い」）
- わかってきたことを束ねた発見の仮説を既存のDiscoveryと突き合わせ、候補にする判断材料（DEC-0009 決定7）を満たすものを提案として出す。1人の参加者の1つの発言だけからは確定候補・派生候補にしない
- 派生が確定した後、元のDiscoveryに投稿されたPostが派生した話の続きかを判断し、結果をC26（みんなの声）の「続きの投稿への注記」に使う（求め方は、話題を外したため見直す。DEC-0015 の Deferred）

### 再チェック（上位の経路。DEC-0018 決定3）
| いつ | 対象 |
|---|---|
| 出来事のとき | 「違うのでは」・通報が付いた、Valueなどへの採用の候補になった（採用の前は必ず上位モデルか人） |
| 定期（週1回） | 確かさの消失、大きな変化、除外の偏り（除外の理由ごとの件数）、ランダムな抜き取り（上位モデルで数十件、一部を運営が見る） |
| モデル・指示を変えたとき | 評価用の一式と、前の版との抜き取りの比べ |

### 予算と縮退（DEC-0018 決定4）
- 解析の実行ごとに使った額を計算し、段階に応じて減らす：注意（ランダムな抜き取りを止める）→ 縮退（定期の見直しを止める、主張の多いDiscoveryの更新の間隔をあける）→ 最小（2段目を優先度の高いDiscoveryから。1段目は続ける）→ 解析を止める（通常の枠の上限）
- 関所と、通報・「違うのでは」の確認は、とっておく枠で続ける
- 縮退で反映が遅れているDiscoveryを、C25の表示のために示す

### 記録（DEC-0018 決定5）
- 解析の実行ごとに、モデルの正確な版、推論の設定、指示の版、入出力のトークン数、費用を残す。主張・わかってきたこと・問いは、どの実行で作られたかをたどれるようにする

### 動かし方（DEC-0017・DEC-0018 決定6）
- EventBridge SchedulerからECSのタスクとして起動し、終わったら消える。起動のたびに設定を読む
- バッチのAPIを使う場合は、「依頼を送る」と「結果を取りに行き、確かめて反映する」の2つの処理に分け、状態をDBに残す
- 画面・APIを圧迫しないよう、DBの接続の数を絞る

## 結果を表示する場所
| 結果 | 表示先 |
|---|---|
| わかってきたこと（説・価値） | [C25（わかってきたこと）](../components/C25-discovery-emerging-terms.md)。関所で保留中のものは出さない |
| 縮退で反映が遅れていること | C25の控えめな表示（「新しい投稿は、まだ反映されていません」など） |
| 問い | 見せ方は別に決める（わかってきたことの中、またはDiscoveryの「こんな情報を求めています」。DEC-0015 決定5） |
| 派生した話の続きかどうか（見立て） | [C26（みんなの声）](../components/C26-post-thread.md)の「続きの投稿への注記」 |
| 派生の確定（提案の確定後。判断記録を伴う） | C26（みんなの声）の「会話の中の目印」、[S03（Discovery詳細）](../screens/S03-discovery-detail.md)の「この発見から広がったDiscovery」 |
| 内部で持つタグ | 画面には直接表示しない。タグによるDiscoveryの露出（S01・S02）と、[F04（タグの補完）](F04-tag-suggest.md)の辞書に使う |
| 主張・解析の記録・使った額 | 画面には出さない（運営の確認の場所は#37と合わせて検討） |

## 検討事項
- 1段目を投稿のときに回すか（#35・F03の判断のあと。DEC-0018 決定1）
- 前回のわかってきたこととの対応づけの基準、文脈の範囲の値の調整
- 問いの画面での見せ方と、回答済み・未回答の扱い（DEC-0015）
- 候補にする判断材料の数値の閾値（Issue #61）、採用（確定）の判断と運用（Issue #46）
- C26の「続きの投稿への注記」の求め方（話題を外したため）
- 本機能と[F03（似たDiscoveryの案内）](F03-similar-discovery-guide.md)の境界。F03は投稿直後に同期的に結果を返す必要があるため、分けて定義した（判断待ち。Issue #67に記録）
- モックでは実際の解析を行わず、固定のデータで表示を確認する
