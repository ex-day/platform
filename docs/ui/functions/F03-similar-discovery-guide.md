# F03: similar-discovery-guide（似たDiscoveryの案内）

## 状態
- **番号・機能の分け方は候補**。Issue #67のPRでAIが提案し、人間がレビューで確定する（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

## 関連概要
新しい話を始める投稿（[C27（新しい話を始める）](../components/C27-post-new.md)）の直後に、似た既存のDiscoveryと、そのわかってきたこと（Finding）を探して返す。投稿を止めるためではなく、質問した人の目的（答えを知りたい）をその場で満たし、既存の会話に加わる選択肢を示すために使う（[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md) 決定1）。

## 入力
- 投稿したPost（本文、表示するタグ）と、その器として作られた成立前のDiscovery

## アクション
- 投稿の確定後に、似た既存のDiscoveryを0..n件探す。0件も正常とする
- 見つかったDiscoveryごとに、表示するわかってきたこと（説・価値）を添えて返す
- 投稿前には呼ばない。既に同じ問い・話があるかを投稿前に確かめさせない（DEC-0010 決定1）
- 結果を返したことで、新しいPostや器のDiscoveryを消したり、既存のDiscoveryへ移したりしない。同一かどうかの判断と統合は、[F02（投稿後の会話の解析）](F02-conversation-analysis.md)の提案と判断を経る（DEC-0009 決定7、DEC-0010 決定1）

## 結果を表示する場所
- C27（新しい話を始める）の投稿直後の表示。文言は「既に同じ質問があります」のように咎める言い方にせず、「同じことを気にしている人がいます」「こんなことがわかっています」のように関心を分かち合う言い方とする

## 検討事項
- 似ていると判断する基準と件数の上限（Issue #46、#61）
- F02（投稿後の会話の解析）と分けるか、1つの機能にまとめるか（判断待ち。Issue #67に記録）
- モックでは実際の検索を行わず、固定のデータで表示を確認する
