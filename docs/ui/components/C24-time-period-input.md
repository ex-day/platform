# C24 time period input
## 機能概要
時期・期間入力（Time Period Input）。季節・時間帯の簡易指定だけでは表現しきれない、時期・日付・期間・時刻を入力する共通コンポーネント。

[S04 知識・疑問登録／編集](../screens/S04-contribution-save.md)では、ContributionからS11以降の解釈に必要な時間情報を取得するため、「詳しく指定」から利用する。[DEC-0002](../../decisions/DEC-0002-contribution-temporal-information.md)に従い、C24自身は入力情報のDiscovery／Valueへの帰属や変換結果を判断しない。当初はDialog内で利用するが、C24の責務は入力とその情報の受け渡しとし、Dialog専用には固定しない。

## 対象端末
- PC
- モバイル

## 入力情報・責務
- 時期・日付・期間と時間From-Toは必要に応じて併用できる。時期だけ、日付だけ、時間だけでも入力できる。
- 毎年の月日範囲と年を含む特定の日付・期間を区別できるようにし、ユーザーが選んだ指定方法も保持する。年のない表現に現在年を補ったり、年の省略だけから毎年の繰り返しと断定したりしない。
- 「4月初旬」を特定の日付範囲へ変換する等、曖昧な表現の正規化を強制しない。ユーザーの入力原文、選択内容、明示的に入力した日付・時刻を区別して保持し、後段で解釈・確認できるようにする。
- 自由入力に対応し、日付・時刻の構造化欄へ収まらないことだけを理由に情報を破棄しない。推定値で原文を上書きしない。
- 入力情報を1つのDiscoveryやValueに割り当てたり、Contributionから形成するDiscovery／Valueの数を決めたりしない。投稿日時・公開日時や資料の撮影・作成日時とも自動的に同一視しない。
- 表示項目の物理名・データ項目はUI上の識別用であり、API契約、永続化形式、TimeExpression・Condition等との対応は本Componentでは確定しない。

## アクション
- 初期表示時
  - 呼び出し元に入力済みの内容がある場合、指定方法・原文・日付や時刻を欠落なく復元する。
- 指定方法・時期・日付・時間を入力または変更
  - 指定方法に応じた入力を表示し、時間From-Toと併用できるようにする。指定方法を切り替えても、非表示になった入力を暗黙に削除・変換しない。
  - 入力内容の確認表示を更新する。意味が曖昧な場合は原文のまま保持し、後段の確認材料として渡す。
- 呼び出し元へ反映
  - 入力内容と選択状態を返す。S04では季節・時間帯の簡易指定も維持し、C24の入力で上書きしない。
  - Dialogで利用する場合は、呼び出し元が「設定」「キャンセル」「詳細指定を解除」の操作を用意する。「設定」は編集結果を反映し、「キャンセル」は開く前の入力を維持し、「詳細指定を解除」はC24の詳細だけを解除する。いずれもDialogを閉じる。
  - Dialog以外での反映・キャンセル操作や配置は呼び出し元で定め、C24自体にDialogの開閉を必須としない。

## 検討事項
- PC／モバイルでのカレンダー、月日範囲、時刻入力と自由入力の組み合わせ、詳細な文言・配置はWireframe／Mockで検証する。
- 年またぎ、日またぎ、片側のみのFrom-To、タイムゾーン、複数期間・除外日等の詳細な入力・検証方法は未確定。曖昧な内容は原文で保持し、期間の前後関係や繰り返し規則を勝手に補わない。
- 複数の季節・時間帯・期間の対応関係、解釈候補の提示・ユーザー確認、正規化・ドメインへの対応付けはS11以降の設計で検討する。
- 入力負荷、S11への入力移動、中間補完、AIとの対話式入力はDEC-0002の未決事項を維持し、Mock／実装以降で評価する。
