# C01 header
## 機能概要
アプリケーション共通のナビゲーション領域を表示する。新規投稿（新しい話を始める）の入口「話す」を持つ（Issue #67「判断：新規投稿の動線」）。

## 対象端末
- PC
- モバイル

## 表示項目

|------------------------|---------------------------------|------------|----------|----|----------|------------|-------------|------|
| ブランドロゴ           | brand_name                      | image/link | -        | -  | -        | -          | PC/モバイル |      |
| 検索                   | → [C06](./C06-search.md)        | component  | -        | -  | -        | -          | PC/モバイル |      |

## アクション
- ブランド名押下
  - S01: TOP画面へ遷移
- C06で検索を実行
  - 指定した検索条件を引き継いでS02 Discovery探索一覧へ遷移する。S02上で実行した場合は同画面の一覧を更新する
- 「話す」押下
  - [C27（新しい話を始める）](./C27-post-new.md)をモーダル（モバイルでは全画面のシート）で開く。URLは`/posts/new`とし、開く前の画面を背景に残す
  - 未ログインでも開き、入力を始められる。ログインは投稿の確定時に求める（[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md) 決定2）

## 構成方針
- ヘッダーの入口は、常に「新しい話を始める」専用とする。S03（Discovery詳細）の中のC26（みんなの声）の入力欄は「この話に加わる」専用とし、両者を区別する。
- アイコンだけでは、どちらの投稿か迷いやすいため、ラベルを添える。ラベルは「話す」とする（Issue #67「判断：Postのユーザー向けの表示名（暫定）」）。
- PC・モバイルともヘッダーに置く。モバイルで画面右下に浮かぶボタンにする案は、S03の下部のコメント欄と重なり混乱しやすいため、採用しない。
- 常に入力フォームを表示する案は、S03のコメント入力と混同しやすいため採用しない。

## 検討事項
- モバイルでは画面下部への配置も検討する（新規投稿の入口は、上記のとおりまずはヘッダーに統一する）
- 画面下部へ配置する場合、ライセンス表記等の配置を再検討する
- 「話す」の入口の具体的なアイコン（「＋」かペンか）と、狭い画面でのラベルの見せ方はWireframe・モックで確認する
