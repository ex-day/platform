# C25 discovery-emerging-terms（わかってきたこと）
## 機能概要
会話から「何がわかってきたか」を表すわかってきたこと（Finding）を、**説**と**価値**の2種類に分けて示し、種類ごとのリアクションを扱うコンポーネント（[DEC-0009](../../decisions/DEC-0009-conversation-understanding-and-tags.md) 決定4・9）。わかってきたことは、[F02（投稿後の会話の解析）](../functions/F02-conversation-analysis.md)が会話全体を解析して作成・更新する、ex-dayの見立て（見立ての層）であり、Discoveryの成立状態や採用したValueには含めない（[DEC-0006](../../decisions/DEC-0006-discovery-state-responsibilities.md)）。

旧定義では、Contributionから抽出された未確定の「語句」を並べるものとしていた。DEC-0009により、語句ではなくわかってきたこと（説・価値）を示すものに改めた。IDとファイル名は変えていない（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

| 種類 | 例 | 意味 |
|---|---|---|
| 説 | 「水害対策では」「汽車道は旧貨物線の一部だった」 | 何がそうなのか・なぜなのかについての説明。観察（「入口が一段高い」）を含む。資料（出典）の裏付けがあるものを知識として扱う |
| 価値 | 「夕方、夕焼けが綺麗」「高低差の理由を一緒に考える」 | その場所・対象の魅力。疑問起点の価値（「謎を一緒に考える」）を含む |

問いはわかってきたことに含めない。問いは声（Post）であり、問いへの「自分も気になる」は、問いを投げた声（C26（みんなの声））に付ける。

## 対象端末
- PC
- モバイル

## 表示項目
| 論理名 | 物理名 | 種別 | 繰り返し | 親 | データ元 | データ項目 | 対象端末 | 備考 |
|---|---|---|---|---|---|---|---|---|
| 見出し | - | text | - | - | 固定 | - | PC/モバイル | 「わかってきたこと」 |
| 価値の一覧 | finding_values | list | 0..n | - | API | findings（kind=価値） | PC/モバイル | 0件の場合は種類の見出しごと表示しない |
| 説の一覧 | finding_theories | list | 0..n | - | API | findings（kind=説） | PC/モバイル | 対立する説は、無理に一つにまとめず並べて表示する（DEC-0005 決定9）。0件の場合は種類の見出しごと表示しない |
| わかってきたことの文 | finding_text | text | - | 各一覧 | API | text | PC/モバイル | まだ見立てであることが分かる見せ方とする（断定の書き方にしない） |
| 裏付けの表示 | finding_backed | text/link | 0..1 | 説 | API | backedBy | PC/モバイル | 資料（出典）の裏付けがある説に表示する。押下で該当の資料を確認できる |
| リアクション | → [C10](./C10-reaction-button.md) | component | 0..1 | 各一覧 | - | - | PC/モバイル | 種類ごとに下記のとおり。数は表示してよいが、説の並びを票の多さで正解のように見せない |

### 種類ごとのリアクション（DEC-0009 決定9）
| 対象 | リアクション | 注意 |
|---|---|---|
| 価値 | 「わかる」「行ってみたい」 | 確からしさ・推薦の材料になる |
| 説（裏付けのないもの） | 「そうかも」 | 正しさの証拠にはしない。票の多い説を正解のように見せない（「Reactionの数を事実の正しさに置き換えない」原則） |
| 説（裏付けのある知識） | 付けない | 確からしさは資料・出典で決まる。代わりに裏付けの表示を出す |

## アクション
- 初期表示
  - Discoveryに属するわかってきたことを取得し、価値と説に分けて表示する。全体で0件の場合は本コンポーネント自体を表示しない
  - 失効したわかってきたことは表示しない（消さずに残すのはデータ上の扱い）
- リアクションボタン押下
  - ログイン済みの場合、わかってきたことの現在の版に対するリアクションとして記録する（版の履歴と、Reactionがどの版に付けられたかを保持する。DEC-0009 決定4）
  - 未ログインの場合、C08（ログイン認証ダイアログ）を表示する
- 再解析で表現が変わった場合
  - 同一性のルール（DEC-0009 決定4）に従い、更新なら同じ項目として表示を変え、リアクションを引き継ぐ。別の新しいものなら新しい項目として並べる

## 構成方針
- S03（Discovery詳細）では、Hero（C19）の直後・本文の前に配置する。
- 価値のわかってきたことは、採用されるとValue（その他の魅力＝C12、Hero＝C19）になる。採用後の表示の移り方は検討事項とする。

## 検討事項
- わかってきたことを見せる基準（「わかってきたこととして見せる」段階の基準）と、数値の閾値（Issue #61）
- 採用（確定）の判断と運用（Issue #46）、価値がValueとして採用された後にC25から外すか、C12・C19へ移ったことを示すか
- わかってきたことを押下したとき、出所となった声（C26（みんなの声））へスクロールする等の挙動の要否
- 件数が増えた場合の表示上限・並び順（説を票の多さで並べない前提で）
- リアクションの具体的な見た目（アイコン・文言）
- ファイル名のスラッグ（`discovery-emerging-terms`）は旧定義の「語句」に由来する。スラッグを`discovery-findings`等に変えるかは判断待ち（Issue #67に記録）
