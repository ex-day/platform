# C19 discovery-detail-hero
## 機能概要
評価済みRecommendationを受け取り、「このDiscoveryについて、今ユーザーに最も伝えたい価値」を直感的に提示するコンポーネント。画像・映像がない場合も、Valueを伝えるテキストを中心に成立する。

C13「今のおすすめ」の価値を伝える責務を統合する。おすすめ理由は価値表現に活かし、独立した項目としての表示を必須にしない。S03でC13と重複表示せず、C12は「その他の魅力」のValue表示として継続する。

## 責務と入力情報
- C19の責務は、評価済みRecommendationに基づく価値の提示と、複数Recommendation間の表示切替である。
- Subject・Condition・Context・Discovery状態は、Recommendationの生成やHeroの表示内容を決める入力情報である。そのままユーザー向け表示項目として列挙しない。
- C19はRecommendationの評価ロジックを持たない。Valueの生成、ConditionとContextの評価、推薦順位の算出、Discovery状態の判定はC19の外側で行う。
- 評価済みRecommendationと対象Value、表示に必要な文言・関連Media等を受け取る。評価結果から表示文言・Mediaを用意する担当と具体的なデータ契約は未確定であり、新たなEntityやAPI項目をここでは確定しない。
- タイトル・本文・C10リアクション・みんなの声（C26）への導線はS03の責務を維持する。

## 対象端末
- PC
- モバイル

## アクション
- 初期表示（Recommendationがある場合）
  - C19の外側で評価されたRecommendation群と、表示に必要な情報を受け取る。
  - 選択中のRecommendationについて、今伝えたい価値をメッセージと任意の画像・映像で提示する。初期選択・表示順は未確定とする。
  - 季節Valueでは、例えば桜の写真を大きく使い「今、桜が見頃です」と伝える。現在の見頃を裏付ける評価結果がある場合の表現例であり、季節の一致だけからC19が実状を推測しない。
  - 疑問起点のValueでは、声（Post）とともに提供された写真等と「この場所について疑問が寄せられています／一緒に考えませんか？」等で参加を促せる。状態コードを表示したり、未確定の答えを事実として伝えたりしない。
  - Mediaがない場合はValueを伝えるテキストを中心に提示する。Mediaや代替画像の生成を必須としない。
- 初期表示（Recommendationが0件の場合）
  - Heroを非表示にせず、Discoveryの状態にかかわらず同じ位置に表示する（Issue #50。比較案D「非表示」・E「最小表示」は採用しない）。
  - 起点となった声（Post）とともに提供された写真・資料がある場合は、それをHeroの画像として利用できる。疑問起点の場合は「一緒に考えませんか？」等の参加表現と組み合わせてよい。
  - 写真・資料がない場合は標準Heroを表示する。ユーザーが意図していない対象イメージを補完しないよう、対象を推測した画像や代替画像を生成・表示しない。
  - 現在成立しないValueを推薦として補充しない。
- Recommendation切替時
  - 選択に応じて価値のメッセージ・参加表現・関連Mediaを整合させる。切替自体による再評価はC19の責務としない。

## 検討事項
- 標準Heroの具体的なデザイン・文言（Issue #52）。表示すること自体はIssue #50で決定済み。
- 起点の写真・資料をHeroに利用する条件（複数ある場合の選び方、出典が未設定の資料を利用する場合のC23との関係）と、探索の進行に伴うHeroの中身の成長のさせ方（Issue #52）。
- Recommendation切替の初期選択、表示順、PC／モバイルの配置・具体的操作。切替UIはサムネイルを採用する。
- 評価結果から価値を伝える文言・Mediaを用意する担当、入力契約、おすすめ理由を表現へ反映する方法。
- 現在Contextの基準、状態・時間の変化時の外部での再評価と選択保持。
- 評価不能、取得失敗、公開・推薦制約がある場合の表示。
- 疑問時の具体文言と参加導線。参加の場はS03に埋め込んだみんなの声（C26）とし、S06への導線は設けない（DEC-0005、Issue #48）。Heroの参加表現とC26の関係。
- Mediaの選択・複数件・動画再生・出所表示・Valueとの対応、画像なし時の構成。過去の写真を現在の実状と誤認させない表現。
- Hero内部でC12を再利用するかは、C12の表示項目をそのまま持ち込むことを前提とせず、Wireframeで確認して判断する。
- タイトル・本文・C10リアクション・みんなの声（C26）への導線とHeroの配置上の関係。
- Discovery状態の具体的な種類・遷移とCondition詳細構造はDomain／Entity側の検討に従う。
