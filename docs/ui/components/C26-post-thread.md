# C26 post-thread（みんなの声）
## 機能概要
Discoveryの会話（Post）を時系列に表示し、その場で自分の声を寄せられるようにするコンポーネント。S03（Discovery詳細）の見出しは「みんなの声」とする。Post（声）は会話の中の発言であり、新しい話を始める最初の発言も返信も対等に扱う（[DEC-0008](../../decisions/DEC-0008-rename-contribution-to-post.md) 決定2）。S05・S06へ遷移せず、S03上で完結する（[DEC-0005](../../decisions/DEC-0005-contribution-thread-and-comment.md)）。

旧名は「コメント（Contribution Thread）」（`C26-contribution-thread.md`）。DEC-0008によるPostへの改称と、Issue #67の判断（表示名、Post間の参照、タグ、派生の誘導）に合わせ、IDを保ったまま名前と中身を変えた（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

### 画面の言葉（Issue #67「判断：Postのユーザー向けの表示名（暫定）」）
| 場面 | 言葉 |
|---|---|
| 集まり（見出し） | みんなの声（1件しかなくても使う） |
| 1件1件 | 声（例：「3件の声」「あなたの声に返信がありました」） |
| 入力欄の案内文（この話に加わる） | 「この話に声を寄せる」「あなたの声を聞かせてください」等。最終的な文言は画面の反映時に決める |
| 送信ボタン | 送る |

分かりやすさが大事な場面（ヘルプ、エラー表示等）では「投稿」を使ってよい。

## 対象端末
- PC
- モバイル

## アクション
- 初期表示
  - Discoveryに属する声を時系列で取得する
  - 声の総数が表示上限n件以下の場合はすべて表示し、「過去のやりとりをすべて見る」は表示しない
  - n件を超える場合、直近n件を常時表示し、それ以前の声を折りたたむ
  - 派生の目印は、派生が確定した時点の位置に表示する。折りたたまれた範囲にある場合は、展開したときに表示する
- 「過去のやりとりをすべて見る」押下
  - 折りたたまれていた声を展開表示する。件数が非常に多い場合のページング方式は検討事項とする
- 「返信する」押下
  - 入力欄に返信先を設定し、返信先を小さく引用して表示する
  - 返信先が派生した話題の声の場合（派生先で続いていると判断されている場合）は、派生先で話す提案を表示する
- 返信先の引用を押下
  - 返信先の声へスクロールする。折りたたまれている場合は展開する
- 入力欄に入力
  - 「#」に続けて入力すると、F04（タグの補完）で補完候補を表示する
  - 本文中の言葉のうち既存のタグに一致するものを、入力欄の下にチップで表示する。タップで本文中の言葉をタグにする
  - 入力中にAIによる解析は行わない（[DEC-0003](../../decisions/DEC-0003-s04-s11-ai-analysis-boundary.md)）
- 「送る」押下
  - ログイン済みの場合、新しい声として末尾に追加する。返信先を設定していた場合は、Post間の参照（返信）として保存する
  - 未ログインの場合、C08（ログイン認証ダイアログ）でログインを求め、入力内容をログイン後に引き継いで送る（DEC-0010 決定2）
  - 投稿の成立は解析の完了を待たない。投稿された声は、F02（投稿後の会話の解析）の入力となり、結果はC25（わかってきたこと）・続きの投稿への注記・派生の目印に表れる
- 派生先で話す提案に従う
  - 派生先のS03へ遷移し、入力内容を派生先の入力欄に引き継ぐ。提案を閉じた場合は、そのまま元の場所に送れる
- 派生の目印・続きの投稿への注記・派生先の冒頭の経緯を押下
  - 対象のDiscoveryのS03へ遷移する
- タグを押下
  - タグを条件にS02（Discovery探索一覧）へ遷移する
- 自分の声の編集・削除
  - 自分の声は、会話の中でその場で編集・削除できる（旧S04（知識・疑問登録／編集）の編集の置き換え。Issue #67）。編集履歴の扱いは検討事項とする
- 「資料・画像を追加する」押下
  - 資料・画像を選択すると、C23を経由せず、出典状態＝未設定のまま即座に声とともに提供・公開する。提供先はDiscoveryとする（DEC-0005 決定8）
  - 出典を選択時に登録したい場合は、添付操作とは別にC23を任意に呼び出せるようにする
- 添付資料の出典表示（「出典：〇〇」「出典：未設定」）を押下
  - C23を表示し、出典状態・出典情報を登録または編集する。呼び出し元が投稿者本人か他の参加者かは問わない（検討事項参照）

## 構成方針（Issue #67「判断：派生の誘導の見せ方」）
- 会話は時系列に並べる形とし、ツリー表示にしない。モバイルで読みにくくなるうえ、話題は連続しておらず、1つのPostが複数の話題にまたがることがあるため、ツリーの枝と話題が一致しない（DEC-0009）。
- 返信の関係（PostReference）は、ツリーではなく返信先を小さく引用して表示する形で示す。
- 派生の誘導は、会話の中の目印・続きの投稿への注記・返信するときの提案・S03の「この発見から広がったDiscovery」の枠の組み合わせとする。続きの会話を派生先で行うよう誘導するが、強制しない（DEC-0009 決定8）。
- 続きの投稿への注記は見立て（DEC-0009の見立ての層）なので、派生の目印より控えめな見た目にする。

## 検討事項
- 【未決（Issue #53）】以下は引き続き未決とする。Wireframe（Issue #48）とNext.jsモック（Issue #50）で使用した「直近n=2件」「過去のやりとりを全件展開」は、確定仕様ではなく比較・検証用の仮値である
  - 閉じた状態で常時表示する直近の声の件数n
  - 開いた状態で一度に表示する声の件数
  - 声の数が多い場合のページ送り／追加ロード等の要否・方式
- 起点となった声（新しい話を始めた最初の声）を一覧上で示すかどうか、示す場合の表現（Issue #53。Next.jsモックでは仮に目印を表示している）
- みんなの声は探索開始直後から推薦可能になった後まで、同じ構成のまま継続して表示する（Issue #50のモック検証で確認）。「探索開始直後」「推薦可能」等はView上の表現であり、Discoveryのドメイン状態（成立状態`UNESTABLISHED`／`ESTABLISHED`）とは一対一に対応しない（[DEC-0006](../../decisions/DEC-0006-discovery-state-responsibilities.md)）
- 出典表示の具体的なフォーマット
- 【追加（Issue #48）】資料添付時に出典登録を必須にすると投稿障壁になるため、添付は即時公開・出典登録は任意かつ事後（あとから重要と分かった時点等）に行える設計とした。この方針の詳細（登録を促すタイミング、投稿者以外による登録・編集の可否）はC23の検討事項を参照
- タグを押下したときの遷移先（本定義ではタグを条件にしたS02（Discovery探索一覧）とした。本PRの案。Issue #67に判断待ちとして記録）と、S02でのタグ条件の表示方法
- 返信以外のPost間の参照（メンション・引用）を画面でどう付け・どう見せるか（DEC-0007 決定8）
- 派生先で話す提案を出す条件（返信先の声が派生先の話題に参照されている場合等）と、提案を閉じた後にもう一度出すか
- 自分の声を編集・削除したときの履歴の扱いと、わかってきたことの出所・派生の判断記録に固めた根拠との関係（DEC-0009 決定1）
- S06（知識・疑問一覧）の要否と再構成（[Issue #68](https://github.com/ex-day/platform/issues/68)）
