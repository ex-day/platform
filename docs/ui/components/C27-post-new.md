# C27 post-new（新しい話を始める）

> **番号は候補**。Issue #67のPRでAIが提案し、人間がレビューで確定する（[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)）。

## 機能概要
新しい話を始める投稿（新規投稿）を行うモーダル。C01（共通ヘッダー）の入口「話す」から開く。投稿すると、そのPost（声）を器に入れる成立前（`UNESTABLISHED`）のDiscoveryが生まれる（[DEC-0006](../../decisions/DEC-0006-discovery-state-responsibilities.md)）。既存のDiscoveryの会話に加わる投稿は、S03（Discovery詳細）の[C26（みんなの声）](./C26-post-thread.md)で行い、本コンポーネントは使わない。

廃止した[S04（知識・疑問登録／編集）](../screens/S04-contribution-save.md)の新規登録の役割を置き換える。投稿時に種類（知識／疑問）・場所・時期を入力させず（[DEC-0005](../../decisions/DEC-0005-contribution-thread-and-comment.md) 決定1・8）、投稿前の確認画面（廃止したS11（知識・疑問登録確認画面））を経ない。解析は投稿後に行う（[F02（投稿後の会話の解析）](../functions/F02-conversation-analysis.md)）。

根拠：Issue #67「判断：新規投稿の動線」「判断：Postのユーザー向けの表示名（暫定）」「判断：タグのMVPでの扱い」、「[判断：タグの入力と表示](https://github.com/ex-day/platform/issues/67#issuecomment-5826926978)」、[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md)。

## URL
- `/posts/new`
- 他の画面から「話す」で開いた場合は、開く前の画面を背景に残したままモーダルとして表示する（Next.jsのルートの横取り表示を想定）。
- URLを直接開いた場合（再読み込み・共有を含む）も、同じ内容を表示できる。

## 対象端末
- PC：モーダル
- モバイル：全画面のシート

## アクション
- 初期表示
  - 見出し「新しい話を始める」と入力欄を表示する
  - 未ログインでも入力を始められる（DEC-0010 決定2）
  - 場所・時期・関連先・種類の入力は求めない。今いる場所や近くのDiscoveryを前提にしたタグの候補も使わない（新規投稿では場所が確定していないため）
- 本文を入力
  - 「#」に続けて入力すると、F04（タグの補完）の候補を表示し、選ぶと本文中にタグとして入る
  - 本文中の#タグは、入力欄の中でそのまま強調して表示する（F04）。文中の言葉からのチップは廃止した（Issue #67「[判断：タグの入力と表示](https://github.com/ex-day/platform/issues/67#issuecomment-5826926978)」）
  - 該当するタグがない場合は、ユーザーが自分の言葉で「#」を付けてタグにできる
  - 入力中にAIによる解析・対話は行わない（[DEC-0003](../../decisions/DEC-0003-s04-s11-ai-analysis-boundary.md)）
- 資料を追加
  - PCではファイル選択とドラッグ＆ドロップ、モバイルでは端末のカメラ、写真・動画ライブラリ、ファイル選択等から追加できる
  - 追加直後の出典状態は未設定とする。出典情報がないことだけでは投稿を拒否しない
- 「送る」押下
  - 本文または資料の少なくとも一方があることを検証する。禁止ワード・不適切資料のチェックを行う（方式は[Issue #35](https://github.com/ex-day/platform/issues/35)）
  - 未ログインの場合、C08（ログイン認証ダイアログ）でログインを求める。入力内容は保持し、ログイン後に引き継いで投稿を確定する。ログインを取りやめた場合も入力内容を失わない
  - ログイン済みの場合、投稿を確定する。器となる成立前のDiscoveryを作り、Postをその中に置く。投稿の成立は解析や候補の確認を待たない（DEC-0005 決定7）
  - 投稿後、F03（似たDiscoveryの案内）の結果を受け取り、投稿直後の表示に切り替える
  - 似たDiscoveryがあっても、投稿前には止めない。既に同じ問い・話があるかを確かめさせない（DEC-0010 決定1）
- 「この話に加わる」押下
  - 似たDiscoveryのS03へ遷移する。投稿した自分のPostと器のDiscoveryは消さず、移さない。同一かどうかの判断と統合は、投稿後の解析の提案と判断を経る（DEC-0009 決定7、DEC-0010 決定1）
- 「自分の話を見る」押下
  - 器として作られた成立前のDiscoveryのS03へ遷移する
- 閉じる
  - モーダルを閉じて開く前の画面へ戻る。URLを直接開いていた場合はS01（Discovery提案）へ戻る

## 構成方針
- ヘッダーの入口「話す」から開くモーダルは「新しい話を始める」専用とし、S03のC26（みんなの声）の入力欄（この話に加わる）と区別する。
- タグは本文と同じ欄で付け、専用のタグ入力欄を設けない（DEC-0009 決定10）。表示するタグは、ユーザーが自分で「#」を付けた言葉だけとする。
- 入力したときの見た目と、投稿後の見た目をそろえる。投稿直後の表示では、投稿した本文中の#タグを、入力欄の強調と同じ見た目で示す。本文の外にタグの欄を設けない。
- C26（みんなの声）の入力欄も、本コンポーネントと同じ入力部品を使い、同じ扱いにする。
- 投稿直後の案内は、質問した人の目的（答えを知りたい）をその場で満たし、既存の会話へ自然に誘導するためのものであり、投稿を咎めるためのものではない（DEC-0010 決定1）。

## 検討事項
- 本文の案内文・投稿直後の表示の最終的な文言（DEC-0010 Deferred）
- 投稿直後の表示から、どちらのS03へ進むかの既定（本定義では両方を選べる形とした。本PRの案。Issue #67に判断待ちとして記録）
- 入力がある状態で閉じた場合の確認・下書きの保持
- 本文の文字数上限、資料の件数上限、許可するMedia Type等（Issue #35）
- 投稿後の器のDiscoveryのタイトル（成立前のDiscoveryの見出し）をどう付けるか（最初の声の冒頭を使う等。後続設計）
- ニックネームの扱いの詳細（DEC-0010 Deferred、S07・S08）
