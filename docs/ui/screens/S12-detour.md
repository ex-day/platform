# S12 寄り道（detour）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（DEC-0022 で寄り道の画面の想定として使った番号。人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号も候補。

## 画面概要

「ここから、この時間で、どこに寄れるか」に答える（B。[DEC-0019](../../decisions/DEC-0019-what-ex-day-wants-most.md)）。移動を始める駅・使える時間・終わり方から、寄れる場所と「そこで何分過ごせるか」を全画面の地図で見せ、寄り道先のまとまり（○○のあたり）と、その上の発見に出会えるようにする。データ（Discovery）がない初期からサービスを支える画面である（[DEC-0013](../../decisions/DEC-0013-detour-suggestion-in-mvp.md)、[MVP スコープ](../../ex-day_mvp_scope.md) 4節）。

## 画面パス

- `/detour?from=<場所の識別子>&to=<場所の識別子>&t=<分>`（DEC-0022 決定5）
- `from` は移動を始める駅で**必須**。終わり方は3択：`to` を省くと移動を始める駅へ戻る（既定）、`to=none` で寄り道先で終わる、`to=<到着の駅>` で別の駅へ向かう（2026-11-20 の人の判断。PR #165）
- `t` は使える時間（分）。時刻では聞かない（DEC-0014）。使える時間の範囲と刻みは、PoC と同じく 30〜480分・15分刻み（**案**）
- 座標を URL に出さない。現在地から始めるときは、まわりの駅を候補に出し、利用者が選んだ駅の識別子を URL にする（2026-11-20。下記「起点と計算の起点」）。座標が要るときは、URL ではなく画面の中の状態として持つ（DEC-0022 決定5）
- 駅・場所の名前は、ページのタイトルと共有の表示（OGP）に出す

## 対象端末

- PC
- モバイル

## アクション

- 初期表示
  - URL の条件（`from`・`to`・`t`）で F06（寄り道の到達圏）を呼び、結果を地図と一覧に出す。`from` がないとき（ヘッダーの「寄り道」から来たとき）は、現在地の近く、または既定のエリアの駅を起点の候補にして、条件の入力を開いた状態で出す。`t` がないとき（S03・S13 の「ここから行ける」から来たときなど）は、TOP の小さな地図と同じく 120分（往復）を既定にする（**案**）
  - 場所のページの「ここから寄り道」や現在地から来たとき（移動を始める駅がまだないとき）は、まわりの駅の候補を出して、移動を始める駅を選んでもらってから F06 を呼ぶ（2026-11-20。下記「起点と計算の起点」）
- 条件を変える（移動を始める駅・使える時間・終わり方・到着する駅）
  - URL を更新して F06 を呼び直す（ブラウザの戻るで前の条件に戻れる）。座標は URL に入れない
- 寄り道先のまとまり を押下：そのまとまりの中の場所と発見を一覧に出し、地図をそこへ寄せる
- 地図の場所 を押下：その場所のカードを一覧で目立たせる。もう一度押すと S13 へ
- 場所カード を押下：S13 へ。発見のカード を押下：S03 へ。戻ると、条件と地図の位置・一覧の位置を保つ
- 戻る を押下：遷移元（S01・S02・S03・S13）へ。遷移元の状態（TOP のスクロール位置と読み込んだカード、S02 の検索の条件と結果の位置など）を保つ（DEC-0022 決定4）。**サービスの中の遷移元がないとき**（共有の URL・ブックマークから直接開いたなど）は S01 へ戻る
  - この「戻る」は、遷移元の画面へ戻る操作であり、条件を変えたことに対するブラウザの戻る（前の条件に戻る）とは分ける
- S02 の「ここから行ける範囲で絞る」から来たとき：S02 の検索の条件を引き継ぐ。**到達圏（どこまで行けるか）は移動の条件（移動を始める駅・使える時間・終わり方・到着する駅）で決まり、その中で出す場所・Discovery は検索の条件で決まる**（2026-11-16 の人の判断）。場所への条件（例：公園。Discovery のない公園も出る）と、Discovery への条件（例：桜の発見）を混同しない。具体的な絞り込み方は後続の機能の設計（F06・F07）で決める

## 起点と計算の起点

到達圏の計算の起点は、MVP では**駅**とする（駅と表定速度で計算する。DEC-0013 決定1、DEC-0014）。**移動を始める駅（帰り道は到着の駅も）は、利用者が選ぶ**（2026-11-20 の人の判断。PR #165。[F06](../functions/F06-detour-reach.md)「想定する使い方」「入力」）。

- 駅から離れた場所では、徒歩より、バスや車で別の駅へ出る人も多く、どの駅を使うかは直線の距離だけでは決められない。MVP ではバスを扱わないので、サービスの側で駅を推定せず、利用者に選んでもらう
- **駅の候補**：現在地、または選んだ場所（場所のページの「ここから寄り道」等）のまわりの駅を、距離の順に数件出す。距離の順は選ぶための補助で、自動で決めたり「おすすめ」としたりはしない。候補にない駅は駅の名前で探せる。最近選んだ駅を上に出す（MVP では端末の中の履歴でよい）
- **終わり方**：「○○駅へ戻る」（既定）は選んだ駅へ戻る。「寄り道先で終わる」は寄り道先で終わる。「別の駅へ向かう」は到着の駅を選ぶ。到着の駅は現在地や出発地のまわりとは限らないので、**帰着する場所の文脈があるとき（目的地の前・途中に寄る等）だけ、その場所のまわりの駅を候補に出し、それ以外は駅の名前での検索と最近選んだ駅から選ぶ**（「別の駅へ向かう」を選んだだけのときは、現在地のまわりの駅は出さない。2026-11-20 の人の判断）
- **まわりの駅の位置づけ**：F06 の入力の決まり・制約ではなく、駅を選ぶための画面の補助
- **現在地・選んだ場所から、移動を始める駅までの移動時間は含めない**。使える時間は「選んだ駅に着いた時点」から数える。画面には「新横浜駅から計算します。現在地・選んだ場所から新横浜駅までの移動時間は含みません」のように出す（目安のお知らせに添える）
- 座標を URL に出さない（DEC-0022 決定5）。現在地のまわりの駅の候補を求める方法と、URL の条件（選んだ場所と、選んだ駅）の形は、F06 の2段目（OpenAPI）で決める

## 構成方針

- **地図が主役**：全画面の地図を広く取り、条件（移動を始める駅・使える時間・終わり方・到着する駅）は上に小さくまとめる。**PC** は地図の横に寄り道先のまとまりと一覧、**モバイル** は地図の下に引き出せる一覧（シート）
- 地図の色は「そこで何分過ごせるか」（寄れる時間＝使える時間 −（移動を始める駅からそこまで）−（そこから終わりまで））。終わり方ごとに：「○○駅へ戻る」は「そこから移動を始める駅まで」、別の駅へ向かうときは「そこから到着の駅まで」を引く。寄り道先で終わるときは最後の項を 0 とし、寄れる場所で旅程を終える（2026-11-19、PR #162 のレビュー）。起点からの距離では塗らない（ドメイン設計 6.5節）
- 寄り道先は、まず「○○のあたり」のまとまりで見せ、白い丸を地図に並べすぎない（PoC のフィードバック：範囲が広すぎる・白い丸が多すぎる）
- **一覧と地図の旗**：寄れる場所の一覧はページで読む（既定20件。F06「ページとカーソル」）。地図の旗は、今のページの場所だけに立てる（読んだ分をためない）。前のページへは、読んだページのカーソルで読み直す。地図の帯（過ごせる時間の色）は到達圏の全体のもので、ページを変えても変わらない。寄り道先のまとまりは、到達圏の全部から集計したものを S12 の取得用 API で受ける（2026-11-20、PR #165 のレビュー）
- 発見のない場所も「声のない場所」として出し、場所のページ（S13）から最初の声につなげる
- 移動時間は「だいたい○○分」として出し、正確な時刻・乗り継ぎの案内はしない（乗換案内のサービスに任せる）
- 本物の地図はこの画面の1つだけにする（TOP の小さな地図は軽く描く。DEC-0022 決定4）
