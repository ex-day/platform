# S04 contribution save
## 画面概要
知識・疑問の新規登録もしくは編集を行う。

## 対象端末
- PC
- モバイル

## アクション
- 初期表示時
  - 未認証の場合も新規作成モードで入力を開始できる
  - S03からDiscovery IDを指定して遷移した場合、遷移元Discoveryを最上部に表示し、関連Discovery候補の強い既知情報として保持する。S04では解除・変更せず、関連付けはS11で確認・変更できるようにする
  - 遷移元Discoveryが場所を持つ場合、その場所をC22の初期入力とする。Contributionの対象場所として固定せず、ユーザーが確認・変更・解除・未指定化できるようにする
  - S03以外から単独投稿する場合、遷移元Discoveryは表示しない
  - 知識・疑問を指定されていた場合、既存の知識・疑問を表示し編集モードとする
  - 知識・疑問を指定されていない場合、新規作成モードとする
- 場所を入力
  - C22をダイアログとして開き、地点／エリア／不明を指定する
  - 現在地、地図、住所・施設名・駅名等の検索から場所を指定できるようにする
- 資料を追加
  - 「資料を追加（任意）」「写真・動画・PDFなど、この投稿に関連する資料を追加できます」と案内する
  - PCではファイル選択とドラッグ＆ドロップを利用できる構成とする
  - モバイルでは端末が提供するカメラ、写真・動画ライブラリ、ファイル選択等につなげられる構成とする
  - 複数の資料を追加・プレビュー・確認・削除できるようにする
  - 追加直後の資料ごとの出典状態は未設定とし、C23から自分で撮影・作成／出典登録済み／出典不明のいずれかを設定できるようにする
- 出典を設定
  - 対象資料のC23を開き、出典状態と出典情報を入力する
  - 複数資料を追加した場合も、資料ごとに出典状態と出典情報を保持する
- 確認へ進むボタン押下
  - 入力内容を検証する 
    - 本文または資料の少なくとも一方が入力されていること
    - 禁止ワード
    - 不適切資料
  - 出典未設定の資料がある場合は件数を案内する。出典情報がないことだけではS11への遷移を拒否しない
  - NG エラー表示
  - OK 入力内容と新規作成／編集の状態を引き継ぎ、[S11 知識・疑問登録確認画面](./S11-contribution-save-confirm.md)へ遷移する
  - S11で「入力内容を修正する」を押下して戻った場合は、入力内容を保持する

## 検討事項
- 投稿確定時に認証を必須とするか、および認証が必要な場合に入力内容を認証後へ引き継ぐ方法は、認証フローと合わせて検討する（Non-blocking）
- 対象年代・時期、季節、時間帯、具体的な成立期間はContributionのContextとして入力し、S04ではDiscoveryの存在・活動期間またはValueの成立条件への割当を確定しない。S11以降で本文・資料と合わせて解釈・確認する
- 年代によって対象の同一性・役割が変わる場合は別Discovery形成の候補になり得るが、年代の指定だけを理由にS04でDiscoveryを自動分割しない
- 季節・時間帯・具体的な成立期間は主にValueの成立条件候補とする。同一Discoveryの複数Valueとして扱うことを基本としつつ、独立性が高い場合に別Discoveryとして形成できる可能性を残す
- 資料の撮影・作成日時と、資料が記録・記述する対象年代は異なり得る。資料メタデータから得た日時を対象年代・時期として自動確定しない。資料ごとの日時・対象年代・キャプション・出典・権利情報の入力方法は画面設計時に検討する
- 出典情報がないことだけでは投稿を拒否しない。未設定のまま投稿確定する場合の確認と、出典不明として保存する方法はS11および画面設計時に検討する
- 出典情報と、資料を投稿する権利・許諾の確認は別に扱う。権利確認の具体的な文言・必須化は利用規約・権利設計と合わせて検討する
- 追加済み資料の件数上限と並べ替えの要否は、Issue #35および画面設計時に検討する
- MVPで許可するMedia Type、ファイルサイズ、動画時間、Live Photos等の扱い、不適切資料の検出・モデレーション方式は[Issue #35](https://github.com/ex-day/platform/issues/35)で確定する。本画面では動画をドメイン／UI上の対象から除外せず、具体的な制限を確定しない
- `contribution_media`は既存ドメイン／論理Entity設計の仮定義Mediaとの対応を示すUI上の名称であり、Mediaの属性・関係やAPI／物理データ構造の最終形は本画面では確定しない
