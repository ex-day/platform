# S04 知識・疑問登録／編集（廃止）

> **廃止（2026-09-25）**。IDは欠番とし、再利用しない。本ファイルは過去の参照のために残す。以下の「廃止前の定義」は当時の記録であり、現在の仕様ではない。

## 廃止の理由と代わり
- 新規投稿はヘッダーの「話す」から開くモーダルで行うこととしたため、独立した登録・編集画面として廃止する（Issue #67「判断：新規投稿の動線」）。あわせて、投稿時に種類（知識／疑問）・場所・時期を入力させない（[DEC-0005](../../decisions/DEC-0005-contribution-thread-and-comment.md) 決定1・8）。
- 代わり：新規投稿は[C27（新しい話を始める）](../components/C27-post-new.md)。既存のPostの編集は、S03（Discovery詳細）の会話（[C26（みんなの声）](../components/C26-post-thread.md)）の中での編集に置き換える。場所・時期の入力に使っていたC22（場所入力）・C24（時期・期間入力）も廃止した。
- 関係するDEC／Issue：DEC-0005、[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md)、[DEC-0011](../../decisions/DEC-0011-id-numbering-rules.md)、[Issue #67](https://github.com/ex-day/platform/issues/67)

## 廃止前の定義

（元の見出し：S04 contribution save）

### 画面概要
知識・疑問の新規登録もしくは編集を行う。本文・資料を主入力とし、気軽に投稿を始められる軽量な画面とする。本文または資料の少なくとも一方があれば「確認へ進む」ことができる。

[Issue #18](https://github.com/ex-day/platform/issues/18)のB案（本文優先＋場所・時期の折りたたみ）を採用し、通常の入力ルートは「種類 → 本文 → 資料 → 確認へ進む」を中心とする。場所・時期は資料より下の「場所・時期を詳しく伝える（任意）」という単独のDisclosure / Collapsibleセクションにまとめ、初期状態は折りたたむ。画面内レイアウトとして扱い、新しいCxxコンポーネントは定義しない。内部の場所入力には既存のC22、詳細な時期・期間入力には既存のC24を利用する。

[DEC-0003](../../decisions/DEC-0003-s04-s11-ai-analysis-boundary.md)に従い、S04内ではContributionのAI解析・自動対話を行わない。「確認へ進む」を契機に、解析完了を待たず入力内容をS11へ渡し、受け取ったS11がContribution AI解析Functionを呼び出す。

[DEC-0002](../../decisions/DEC-0002-contribution-temporal-information.md)に基づき、S11以降でDiscoveryおよびそれに紐づくValueを抽出・判断するための情報を欠落なく取得する。時間情報は解釈前のContributionのContextとして保持し、S04ではDiscovery／Valueへの帰属・変換を確定しない。

### 対象端末
- PC
- モバイル

### アクション
- 初期表示時
  - 場所・時期の任意詳細セクションは折りたたんで表示する。開く操作や詳細入力を、通常ルートでS11へ進むための条件にしない
  - 未認証の場合も新規作成モードで入力を開始できる
  - S03からDiscovery IDを指定して遷移した場合、遷移元Discoveryを最上部に表示し、関連Discovery候補の強い既知情報として保持する。S04では解除・変更せず、関連付けはS11で確認・変更できるようにする
  - 遷移元Discoveryが場所を持つ場合、その場所をC22の初期入力とする。Contributionの対象場所として固定せず、ユーザーが確認・変更・解除・未指定化できるようにする
  - S03以外から単独投稿する場合、遷移元Discoveryは表示しない
  - 知識・疑問を指定されていた場合、既存の知識・疑問を表示し編集モードとする。本文、資料の追加・削除・差し替え、資料の出典情報、場所・時間等のContextは基本的に新規と同じ項目を編集でき、同じ検証条件でS11へ進んで再確認する。投稿種別の変更可否は未確定とする
  - 知識・疑問を指定されていない場合、新規作成モードとする
- 「場所・時期を詳しく伝える（任意）」を押下
  - セクションを展開・折りたたみする。展開時に場所入力と、時間入力の2グループ（「いつの話ですか？」「いつ見たり体験したりできますか？」）を表示する
  - 折りたたみは表示だけを切り替え、入力内容や選択状態を消去・変換しない。S03からの初期入力や編集時の既存値も保持し、展開後に確認・変更できるようにする
  - 未入力と明示的な「不明」を区別し、閉じたままでも保持しているContextをS11へ渡す
- 場所の表示を押下
  - 未設定／設定済み／不明のいずれでも表示自体を操作起点としてC22をダイアログで開き、内容を確認・変更・解除できるようにする
  - C22で「不明」を設定した場合は「場所：不明」等を表示し、「未指定にする」で解除した場合は未設定の案内に戻す
  - 項目名には「場所」を使い、端末の現在地取得手段には「位置情報」を使う
  - 現在地、地図、住所・施設名・駅名等の検索から場所を指定できるようにする
- 「いつの話ですか？」を入力
  - 現在／過去／未来／不明を選択できる。未入力からいずれかへ自動確定しない
  - 過去の場合、時代・年代の詳細入力を表示する。例：中世、戦国時代、昭和30年代、1600年頃
  - 検索可能なサジェストと自由入力を併用し、候補がなくても入力できる。「戦国期」「昭和30年代くらい」等を強制的に標準名称や日付範囲へ変換しない
  - 選択内容と入力原文を保持する。選択変更で詳細欄が非表示になっても原文を暗黙に破棄せず、選択状態と区別して後段へ渡す
- 「いつ見たり体験したりできますか？」を入力
  - 季節と時間帯を組み合わせて指定できる。例：夏＋夕方、通年
  - 「詳しく指定」でC24をDialog内に表示し、毎年・おおよその時期、特定の日付・期間、時間From-Toを入力する。例：毎年7/15〜8/31＋17:00〜21:00、2027/4/3〜2027/4/10
  - C24で設定した内容を表示し、再度開いて確認・変更できる。季節・時間帯とC24の入力内容を併せて保持し、一方の入力で他方を上書きしない
- 資料を追加
  - 「資料を追加（任意）」「写真・動画・PDFなど、この投稿に関連する資料を追加できます」と案内する
  - PCではファイル選択とドラッグ＆ドロップを利用できる構成とする
  - モバイルでは端末が提供するカメラ、写真・動画ライブラリ、ファイル選択等につなげられる構成とする
  - 複数の資料を追加・プレビュー・確認・削除できるようにする
  - 追加直後の資料ごとの出典状態は未設定とし、C23から自分で撮影・作成／出典登録済み／出典不明のいずれかを設定できるようにする
- 出典を設定
  - 対象資料のC23を開き、出典状態と出典情報を入力する
  - 複数資料を追加した場合も、資料ごとに出典状態と出典情報を保持する
- 確認へ進むボタン押下
  - 入力内容を検証する 
    - 本文または資料の少なくとも一方が入力されていること
    - 禁止ワード
    - 不適切資料
  - 出典未設定の資料がある場合は件数を案内する。出典情報がないことだけではS11への遷移を拒否しない
  - 本文も資料もない場合は、本文または資料の入力が必要であることを両項目に対応する位置で案内する。場所・時間・出典情報の未入力だけでは遷移を拒否しない
  - NG エラー表示
  - OK 入力内容と新規作成／編集の状態を引き継ぎ、[S11 知識・疑問登録確認画面](./S11-contribution-save-confirm.md)へ遷移する。S04ではAI解析を呼び出さず、解析完了も待たない。解析中表示・結果確認・再実行・失敗時の扱いはS11側の責務とし、詳細はDEC-0003およびIssue #40で扱う
  - 遷移元Discovery、場所、2グループの時間情報（候補選択・自由入力原文・C24詳細を含む）を引き継ぐ。遷移元Discoveryがあっても他Discovery候補の提示・確認を省略せず、関連付けやValueを自動確定しない
  - S11で「入力内容を修正する」を押下して戻った場合は、入力内容を保持する

### 検討事項
- 投稿確定時に認証を必須とするか、および認証が必要な場合に入力内容を認証後へ引き継ぐ方法は、認証フローと合わせて検討する（Non-blocking）
- 時間入力の2グループは判断材料の整理であり、Discovery／Valueへの対応表ではない。[DEC-0002](../../decisions/DEC-0002-contribution-temporal-information.md)の城址公園／中世の城の例のように、同じ情報から別Discovery、既存Discoveryに紐づくValue、その両方が形成される可能性を残す
- 年代によって対象の同一性・役割が変わる場合は別Discovery形成の候補になり得るが、年代の指定だけを理由にS04でDiscoveryを自動分割しない
- 季節・時間帯・C24の詳細は後段で価値になり得る時間条件の判断材料とする。1投稿を1つのValueに固定せず、複数選択した季節・時間帯の対応関係もS04で解釈・確定しない
- 未来の詳細入力、サジェスト候補の取得元・検索方法、通年／いつでも／不明と他選択肢の併用時の案内は未確定とし、画面設計・Mockで検討する。解釈できない表現や候補にない入力を失わない
- 場所・時期をS04の任意詳細入力として置くのは現段階の配置であり、恒久的な配置としてFixしない。S11設計後に、入力負荷と解析結果の確認・補完の流れを踏まえ、S11への移動等を再評価する（Non-blocking）。情報を欠落なく渡すDEC-0002の要件は維持する
- Disclosure → 時間入力グループ → 「詳しく指定」からC24を開くUI階層は現時点では許容する。PC／モバイルのMockレビューで発見しやすさ・開閉操作・入力負荷を確認し、必要なら見せ方を再評価する（Non-blocking）
- S03からの場所の初期入力や編集時の設定済みContextを、折りたたみ中にも要約表示するかはWireframe／Mockで検討する。遷移元Discoveryの表示とContributionの場所は混同しない（Non-blocking）
- S04入力中のAIによる自動対話・自動解析は採用しない。将来の明示的なオプション機能はDEC-0003の未確定事項として別途検討する。S11のMockはContributionからDiscovery／Valueへの変換設計再開まで保留する（DEC-0002）
- 編集時の投稿種別変更、編集前の原文・訂正履歴の保持、S05/C18からの確認事項の表示・フォーカス、編集時の遷移元Discoveryの表示方法は未確定とする。今回の基本編集方針からこれらを確定しない
- 場所は単一項目の表示自体を操作起点とし、0..n件で追加・削除・出典設定等の複数操作を持つ資料とは操作の構成を分ける
- WireframeではS03起点の対象Discoveryの識別とContributionの場所との区別、単独新規／編集／確認補完の入口別状態を確認する。探索条件の引き継ぎはC21の未確定事項を維持する
- 本文の文字数上限、離脱時確認・下書き、資料アップロードのタイミングと受け渡しは未確定とする。S04／S11の同一ページ化は今回確定せず、現定義のS11への遷移を維持する
- S03投稿導線の整合は[Issue #39](https://github.com/ex-day/platform/issues/39)、S11の詳細な確認項目・Wireframe／Mockの整合は[Issue #40](https://github.com/ex-day/platform/issues/40)で扱う。時間情報の引き渡しは本定義とDEC-0002を参照する
- 資料の撮影・作成日時と、資料が記録・記述する対象年代は異なり得る。資料メタデータから得た日時を対象年代・時期として自動確定しない。資料ごとの日時・対象年代・キャプション・出典・権利情報の入力方法は画面設計時に検討する
- 出典情報がないことだけでは投稿を拒否しない。未設定のまま投稿確定する場合の確認と、出典不明として保存する方法はS11および画面設計時に検討する
- 出典情報と、資料を投稿する権利・許諾の確認は別に扱う。権利確認の具体的な文言・必須化は利用規約・権利設計と合わせて検討する
- 追加済み資料の件数上限と並べ替えの要否は、Issue #35および画面設計時に検討する
- MVPで許可するMedia Type、ファイルサイズ、動画時間、Live Photos等の扱い、不適切資料の検出・モデレーション方式は[Issue #35](https://github.com/ex-day/platform/issues/35)で確定する。本画面では動画をドメイン／UI上の対象から除外せず、具体的な制限を確定しない
- `contribution_media`は既存ドメイン／論理Entity設計の仮定義Mediaとの対応を示すUI上の名称であり、Mediaの属性・関係やAPI／物理データ構造の最終形は本画面では確定しない

表示項目の物理名・データ項目はUI上の識別用であり、APIや永続化構造を確定するものではない。特に時間情報は原文と選択内容を保持する要件を示し、TimeExpression等への正規化・対応付けは後段の設計で扱う。
