# S01 TOP（top）

> 2026-11-16 根本整理（DEC-0019〜0023、[Issue #135](https://github.com/ex-day/platform/issues/135)）と [DEC-0022](../../decisions/DEC-0022-top-page-and-detour-entry.md) に合わせて書き直した。旧名「Discovery提案（サービスTOP）」。v0.3 の定義（C11 の Discovery Sections だけで構成する形）は Git の履歴にある。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号は候補。

## 画面概要

開いたときに **何のサービスかが伝わり**、そのうえで「今いる場所 × 今」を起点に、企画・いまの時期の発見・近くの発見・ここから行ける範囲（寄り道）・場所が決まっていない話・声を待っている場所に出会えるようにする（要求仕様 28節）。

Discovery がほとんどない初日から成り立つことを前提にする。中身のある枠だけを出し、データの量に合わせて重みが自然に移る（DEC-0022 決定2）。初日は企画・ここから・番付・見本・声を待っているが中心で、育ったあとは、いま・この時期と近くの発見が前に出る。

## 画面パス

- `/`
- 今の実装（API のデータで表示。Issue #113。モックは `/mock`）は v0.3 の形のまま。実装の段で移す

## アクション

- 初期表示
  - 起点を決める：**すでに許可されている**現在地があれば、その近くの場所を起点にする。なければ、既定のエリア（始める地域、またはログインしている人の興味のある地域）を起点にする。**TOP を開いた直後には位置情報の許可を求めない**。小さな地図を押す・寄り道を使うなど、位置情報が要る機能を使おうとしたときに求める（2026-11-16 の人の判断）。座標を URL に出さない（DEC-0022 決定5）
  - F01（TOP の枠）で、中身のある枠と重みを決める。空の枠と「0件」は出さない
  - **いま・この時期**は範囲を広げて探す：近く → 同じ区・市 → 全国から1〜2件（「今の時期ならこんな発見も」）→ なければ枠ごと出さない（DEC-0022 決定3）
  - 並びは、同じセッション・その日のうちは変えない（DEC-0022 決定4。日付などを種にした並び）。カードは際限なく増やさず、件数に上限を設ける（例：50件、その先は「もっと見る」）
- 小さな地図 を押下：S12 へ（`from`＝起点の場所、`t`＝120、`to` は省く＝往復）。現在地の許可がまだなら、ここで許可を求め、許可されなければ既定のエリアの起点のまま開く。戻ったら、スクロール位置と読み込んだカードを保つ（DEC-0022 決定4。実装の選択肢として intercepting routes）
- カード を押下：企画は S15、Discovery は S03、場所は S13、探しています は S14 へ。戻ったら、スクロール位置を保つ
- 「こんな番付、作ってみませんか？」 を押下：S16 へ（型＝番付を選んだ状態）
- 枠の「もっと見る」 を押下：S17 または S02 へ、枠の条件を引き継ぐ
- ヘッダーで検索を実行：S02 へ、検索の条件を引き継ぐ
- ヘッダーの「話す」：C27 を、入口なしで開く

## 小さな地図と S12 の条件

TOP の小さな地図が示す移動の条件と、押して開いた直後の S12 の条件を一致させる（PR #146 のレビュー）。

- TOP の既定は **往復・使える時間 120分**（**案**）。S12 の既定（`to` を省くと往復）に合わせ、TOP から寄り道して元の場所に戻ってくる使い方を基本にする
- 文言は「[起点]から、往復2時間で寄れるところ」。「30分で行ける範囲」のような片道に読める言い方はしない（DEC-0022 決定2 の表の「ここから30分で行ける範囲」は例とし、既定の条件は本書で決める）
- 押したときに渡す条件：`from`＝起点の場所の識別子、`t`＝120、`to` は省く（往復）
- 小さな地図の描き方（そこで何分過ごせるかの色）も、この条件で計算した結果を軽く描いたものにする

## 構成方針

- **PC**：真ん中の列に企画と発見の枠、横の列（余白）に小さな地図と「このあたりの数字」（DEC-0022 決定1）
- **モバイル**：一番上に小さな地図のカード、その下に企画と発見の枠のカード
- **小さな地図は軽く描く**：地図のライブラリ（WebGL）ではなく、帯の形を SVG などで描く。本物の地図は S12 の1つだけにする（DEC-0022 決定4 の実装の選択肢。メモリを使いすぎない）
- 枠の重みは F01 が決め、枠の切り替えの仕組みは持たない。初日：企画・ここから・番付・見本・声を待っているが中心。育ったあと：いま・この時期と近くの発見が前に出て、企画は帯に小さくなる
- 推定（番付）・見本・ユーザーの企画は、それぞれ「推定」「ex-day の発見（見本）」「[ニックネーム] さんの企画」と出し、ex-day の認定に見せない
- 既定を地図にする設定は MVP の対象外（DEC-0022 決定6）

## 判断待ち・検討事項

- サービスの紹介を、初めて来た人と何度も来ている人で変えるか（変える案）。文言
- 起点の既定（始める地域か、興味のある地域か）。現在地の許可は、位置情報が要る機能を使おうとしたときに求める（決定）
- 小さな地図の既定の使える時間（120分の案）
- 枠の並びの重みの具体的な決め方（F01）、各枠の件数
- 探しています の枠を、近くに候補がないときにも出すか
- 「あとで見る」の保存（ログインが要るので後で決める。DEC-0022 決定4）
- 地図から戻ったあと、時間をおいて戻った場合の並び・鮮度、保持中に非公開になったものの扱い（実装で決める。v0.3 から引き継ぐ）
