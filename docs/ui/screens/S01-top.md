# S01 TOP（top）

> 2026-11-16 根本整理（DEC-0019〜0023、[Issue #135](https://github.com/ex-day/platform/issues/135)）と [DEC-0022](../../decisions/DEC-0022-top-page-and-detour-entry.md) に合わせて書き直した。旧名「Discovery提案（サービスTOP）」。v0.3 の定義（C11 の Discovery Sections だけで構成する形）は Git の履歴にある。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号は候補。

## 画面概要

開いたときに **何のサービスかが伝わり**、そのうえで「今いる場所 × 今」を起点に、企画・いまの時期の発見・近くの発見・ここから行ける範囲（寄り道）・場所が決まっていない話・声を待っている場所に出会えるようにする（要求仕様 28節）。

Discovery がほとんどない初日から成り立つことを前提にする。中身のある枠だけを出し、データの量に合わせて重みが自然に移る（DEC-0022 決定2）。初日は企画・ここから・番付・見本・声を待っているが中心で、育ったあとは、いま・この時期と近くの発見が前に出る。

## アクション

- 初期表示
  - 起点を決める：**すでに許可されている**現在地があれば、その近くの場所を起点にする。なければ、既定のエリア（始める地域、またはログインしている人の興味のある地域）を起点にする。**TOP を開いた直後には位置情報の許可を求めない**。小さな地図を押す・寄り道を使うなど、位置情報が要る機能を使おうとしたときに求める（2026-11-16 の人の判断）。座標を URL に出さない（DEC-0022 決定5）
  - F01（TOP の枠）で、中身のある枠と重みを決める。空の枠と「0件」は出さない
  - **いま・この時期**は範囲を広げて探す：近く → 同じ区・市 → 全国から1〜2件（「今の時期ならこんな発見も」）→ なければ枠ごと出さない（DEC-0022 決定3）
  - カードは際限なく増やさず、全体で 50件までにする（その先は「もっと見る」）。各枠の並びは枠の意味に合った順（下の「取得用 API で返すもの（案）」）。詳細・S12 から戻ったときは、Web が取得済みのカードとスクロール位置を戻す（DEC-0022 決定4、2026-11-19 改訂）
- 小さな地図 を押下：S12 へ（`from`＝起点の場所、`t`＝120、`to` は省く＝往復）。現在地の許可がまだなら、ここで許可を求め、許可されなければ既定のエリアの起点のまま開く。戻ったら、スクロール位置と読み込んだカードを保つ（DEC-0022 決定4。実装の選択肢として intercepting routes）
- カード を押下：企画は S15、Discovery は S03、場所は S13、探しています は S14 へ。戻ったら、スクロール位置を保つ
- 「こんな番付、作ってみませんか？」 を押下：S16 へ（型＝番付を選んだ状態）
- 枠の「もっと見る」 を押下：S17 または S02 へ、枠の条件を引き継ぐ
- ヘッダーで検索を実行：S02 へ、検索の条件を引き継ぐ
- ヘッダーの「話す」：C27 を、入口なしで開く

## 小さな地図と S12 の条件

TOP の小さな地図が示す移動の条件と、押して開いた直後の S12 の条件を一致させる（PR #146 のレビュー）。

- TOP の既定は **往復・使える時間 120分**（**案**）。S12 の既定（`to` を省くと往復）に合わせ、TOP から寄り道して元の場所に戻ってくる使い方を基本にする
- 文言は「[起点]から、往復2時間で寄れるところ」。「30分で行ける範囲」のような片道に読める言い方はしない（DEC-0022 決定2 の表の「ここから30分で行ける範囲」は例とし、既定の条件は本書で決める）
- 押したときに渡す条件：`from`＝起点の場所の識別子、`t`＝120、`to` は省く（往復）
- 小さな地図の描き方（そこで何分過ごせるかの色）も、この条件で計算した結果を軽く描いたものにする

## 構成方針

- **PC**：真ん中の列に企画と発見の枠、横の列（余白）に小さな地図と「このあたりの数字」（DEC-0022 決定1）
- **モバイル**：一番上に小さな地図のカード、その下に企画と発見の枠のカード
- **小さな地図は軽く描く**：地図のライブラリ（WebGL）ではなく、帯の形を SVG などで描く。本物の地図は S12 の1つだけにする（DEC-0022 決定4 の実装の選択肢。メモリを使いすぎない）
- 枠の重みは F01 が決め、枠の切り替えの仕組みは持たない。初日：企画・ここから・番付・見本・声を待っているが中心。育ったあと：いま・この時期と近くの発見が前に出て、企画は帯に小さくなる
- 推定（番付）・見本・ユーザーの企画は、それぞれ「推定」「ex-day の発見（見本）」「[ニックネーム] さんの企画」と出し、ex-day の認定に見せない
- 既定を地図にする設定は MVP の対象外（DEC-0022 決定6）

## 取得用 API で返すもの（案）

> 2026-11-19 追加（Issue #135 の「API」の段、PR #158）。取得用の API の約束事（OpenAPI）を書く前に、各枠をどの表から読み、どう並べ、何件返すかの案と、決めたいことを書く。同日、1段目のレビューを反映した（並びを固定する役目を Web に移し DEC-0022 決定4 を改訂、枠の順を1つにする、50件の切り方、公開の由来だけを数える、暫定と公開時の条件を分ける）。件数・距離は暫定の値。

**API**

- `GET /top?from={場所の識別子}`：TOP の全部の枠を1回で返す。`from` を省くと、始める地域（アプリの設定にある場所の `public_id`）を起点にする
- 旧 v0.1 の `GET /discovery-sections`・`GET /discovery-sections/{sectionKey}/discoveries` は、3段目でこの API に置き換えて消す。対象：OpenAPI、API の実装・テスト、Web の Route Handler・クライアント・C11 の今の実装、生成した型（`schema.d.ts`）、API・Web の README、F01・C11 の文書。#151 で止めた S01 の DB のテスト（`DiscoverySectionItemsApiTest`・`AutumnDiscoverySectionItemsApiTest`）は、新しい API のテストとして書き直して戻す

**共通**

- 一般のユーザー向けの読み取りなので、公開のビュー（`visible_*`）を通す。1つの応答を REPEATABLE READ の読み取り専用トランザクションで作る（S03・S13〜S17 と同じ）
- **起点**は場所の識別子で受け、座標を受けない（URL・ログに座標を残さない。DEC-0022 決定5）。起点の場所の「位置」は、S15 と同じく経路なら始点、それ以外は面の上の1点（`ST_PointOnSurface`）にする
- **近く**＝起点の位置から直線で 3km 以内（暫定）。TOP の枠の中身を選ぶための決まりで、S12・F06 の移動の条件（往復120分）とは別の意味のまま扱う（下の「小さな地図と F06」）
- **今**は `Clock`（テストで固定できる）から取り、季節は今の `Seasons` の決まり（月→季節）を使う
- **並び**：API は**枠ごとの意味に合った全順序**で返す（下の表）。同じ順位は `public_id`（文字コード）で決める。日付などを種にした、全部の枠・全員に共通の固定の並びは、API の約束にしない。詳細・S12 から戻ったときに見ていた位置やカードを見失わないことは、Web が取得済みの応答とスクロール位置を保ち、戻ったときに戻すことで満たす（DEC-0022 決定4 の改訂、2026-11-19）
- **声のある発見**＝公開の Discovery のうち、由来（`discovery_origin`）に、**公開の会話（`visible_conversation`）または公開の Post（`visible_post`）に届くもの**を持つもの。由来がいくつあっても Discovery は1件と数える。非公開の会話・Post だけを由来に持つ Discovery は数えない（数から非公開のものがあると漏れないように）。**この定義は「このあたりの数字」の集計にだけ使い、Discovery の枠の対象を狭める条件にはしない**（2026-11-19、PR #158 の再レビュー）
- **重ねない**：1つの Discovery・場所は TOP の1つの枠にだけ出す。応答の枠の順で先に出た枠に置き、同じ Discovery を見本の枠へ重ねない
- **見本の表示**：運営の登録（`discovery_origin` の OPERATOR）を由来に持つ Discovery も、公開され成立している以上、正しい Discovery として扱う。条件に合えば、いま・この時期・近くの発見・お知らせにも出す。「見本」は品質を下げる状態や隔離先ではなく、運営が登録した由来を示し ex-day の認定・推薦と誤解させないための表示なので、**どの枠に出ても「ex-day の発見（見本）」と分かる表示を付ける**（2026-11-19、PR #158 の再レビュー）。そのため Discovery のカードに、運営の登録を由来に持つかどうかを渡す（2段目の OpenAPI で `isExample` などの判別の値か表示の情報を決める）
- カードの形は、今ある部品を使う：Discovery は `card.discovery`、企画は `card.project`、場所は S13 の場所の見出し（名称・種類）、推定の値は `estimate.PlaceEstimates`（`apps/api/AGENTS.md` の「機能の責務と名前空間」）

**枠の順（F01）**

- 枠の優先の順は1つだけにし、中身のない枠を省く（DEC-0022 決定2。初日と育ったあとで切り替える仕組みは持たない）。API が並べた順で返し、画面は並べ替えない
- 順（案）：始める地域の外のお知らせ → いま・この時期 → 近くの発見 → 企画 → 番付 → ex-day の発見（見本） → 探しています → 声を待っている
- 条件に合う Discovery がなければ、いま・この時期と近くの発見は省かれ、企画・番付・見本・声を待っているが前に来る（初日はこの形になりやすい）。育つと、いま・この時期と近くの発見が自然に前に出る。企画の枠を「帯に小さく」見せるかは画面の表し方で決め、API の順は変えない
- 起点・小さな地図・このあたりの数字は、枠の並びの外に返す（画面の決まった場所に出す）

**件数（全体で50件まで）**

- 枠ごとの上限（下の表）と、全体の予算 50件を持つ。**応答の枠の順に**、各枠へ「その枠の上限」と「予算の残り」の小さいほうを配る
- 各枠は配られた数より1件多く読み、超えた分があれば `hasMore=true` を返す。全体の予算で切られた枠も、続きがあれば `hasMore=true` にする。「もっと見る」は `hasMore=true` の枠にだけ出す
- 予算が尽きて1件も配られない枠は、中身があっても返さない
- 全体の数は返さない（「もっと見る」は S17・S02 で読む）。中身のない枠は返さない（空の配列にせず、枠ごと省く）

**行政の祖先**

- 起点から `place_relation`（ADMINISTRATIVE・CONTAINS。`from` が親）を親へたどった場所のうち、種類が「市区町村」のものを、近い親から順に「行政の祖先」とする（区があれば区、なければ市）
- たどれる親がないとき（駅など）は、起点の位置を面に含む「市区町村」の場所のうち、面の小さいものから順にする
- 「同じ行政の地域」は、最も近い行政の祖先（区、なければ市）の中（その場所の面に含まれる、または関係で子孫にあたる場所）とする

**いま・この時期の広げ方**

1. 近く：近くの場所を持つものを距離の順に、上限まで
2. 同じ行政の地域：上限に足りなければ、1 で出したものを除き、最も近い行政の祖先の中のものを距離の順に補う。行政の祖先がなければ、この段を飛ばす
3. 全国：1・2 で1件もなければ、全国から距離の順に2件（「今の時期ならこんな発見も」）
4. それでもなければ枠を出さない

**小さな地図と F06**

- 今回は、起点の名前と、条件（120分・往復）、S12 への入口だけを返す
- F06 ができたら、帯の形だけでなく、表示の起点、実際に計算する起点の駅、使える時間・往復、計算できないときの状態、起点から駅までの移動を含まないことなどの注意を、約束事に足す。「近く」の各枠を到達の範囲に変えるかは、その時点で別に決める

**暫定（MVP の途中）と、一般公開のときに必要なこと**

**決めたこと・決めたいこと**（2026-11-19、PR #158 の1段目のレビュー）

1. **並び**：API は枠ごとの意味に合った全順序で返し、戻ったときに見失わないことは Web が取得済みの応答とスクロール位置を保って満たす（決定。DEC-0022 決定4 を改訂）
2. **枠の順**：優先の順を1つにし、中身のない枠を省く（決定）。順は上の案
3. **件数**：応答の枠の順に予算 50 を配り、`hasMore` で続きを示す（決定）
4. **声のある発見**：公開の会話・Post に届く由来を持つ Discovery を一意に数える。この定義は「このあたりの数字」にだけ使い、いま・この時期・近くの発見・お知らせは公開の Discovery 全般を対象にする（決定）
5. **見本**：運営の登録を由来に持つ Discovery も条件に合えばほかの枠に出し、どの枠でも「見本」と分かる表示を付ける。見本の枠には先の枠に出なかったものを出す。声のある発見の数は共通の定義どおりで、**運営の登録だけ**を由来に持つ Discovery は数えず、運営の登録に加えて**公開の会話または公開の Post の由来も持つ** Discovery は声のある発見として数える（決定）
6. **起点**：今回は場所の識別子と始める地域だけ。現在地 → 場所の置き換えは S12 と一緒に後で作る（暫定として可。一般公開までに必要）。ログインしている人の興味のある地域（`user_interest`）は認証（#75）のあと
7. **企画**：地域で絞らず、`GET /projects` を拡張せず、「もっと見る」は条件なしで S17（決定）
8. **近く・小さな地図**：直線 3km と F06 の往復120分は別の意味のまま扱う。小さな地図は今回は条件だけ（暫定として可）
9. **声を待っている**：種類による除外なしで始める（決定）
10. **探しています**：答えの出ていない場所の問いを持つ会話と、問いはないが採用していない検討中の候補を持つ会話の両方を、会話を単位に出す（決定）
11. **旧 API**：3段目で置き換えて消す（決定。対象は上の「API」）
12. 枠の順の案・各枠の上限・3km・行政の祖先のたどり方は、2段目のレビューで改めて見る
