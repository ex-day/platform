# S17 企画の一覧（project list）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号も候補。

## 画面概要

いま募集中の企画（運営のお題とユーザーの作品）を一覧にし、参加と企画づくりの入口にする。TOP の企画の枠の「もっと見る」の行き先（[DEC-0021](../../decisions/DEC-0021-projects-by-operator-and-users.md)、[MVP スコープ](../../ex-day_mvp_scope.md) 8節）。

MVP では企画を閉じる機能を作らないので（PR #144）、「募集中」は公開されている企画のことになる。

## 画面パス

- `/projects`（条件はクエリで持つ。例：`/projects?type=ranking`）

## 対象端末

- PC
- モバイル

## アクション

- 初期表示：公開の企画を、既定の並べ方で出す。TOP の企画の枠から来たときは、枠の条件（近くの企画など）を引き継ぐ
- 絞り込み・並べ方を変える：URL を更新して一覧を読み直す
- 企画カード を押下：S15 へ。戻ると、条件と一覧の位置を保つ
- 企画を作る を押下：S16 へ（未ログインでも入力を始められ、公開のときにログインを求める）

## 構成方針

- 作った人を必ずカードに出し、運営の企画とユーザーの企画を見分けられるようにする。ユーザーの企画を ex-day の認定に見せない
- 並べ方は、企画が会話のきっかけになっているか（新しい声）を基本にし、人気投票・ランキングのようには見せない
- 企画どうしの関連付け（作った人がいなくなった企画を続ける企画など。PR #144）は、仕様が決まるまでこの画面では扱わない

## 取得用 API で返すもの（案）

> 2026-11-18 追加（Issue #135 の「API」の段）。取得用の API の約束事（OpenAPI）を書く前に、読む表と返すもの、決めたいことを置く。レビューで決めたら「決めたこと」に書き直す。

**API（案）**

- `GET /projects`：公開の企画の一覧。絞り込み・並べ方はクエリで受け、「もっと見る」はカーソルで続きを読む

**共通**

- 一般のユーザー向けの読み取りなので、公開のビュー（`visible_project`・`visible_conversation`）を通す。1つの応答を REPEATABLE READ の読み取り専用トランザクションで作る
- MVP では企画を閉じる機能を作らないので、「募集中」＝公開の企画（上の画面概要のとおり）
- 作った人は今のニックネーム（#74）。運営の企画も、作ったアカウントのニックネームを返す（S15 と同じ）
- 数の決まりは S15 と共用する（企画をきっかけにした会話の数は、S15 の `triggeredConversations` の全体の数と同じ範囲）

**返すもの（企画カード C29。案）**

| 項目 | 読む表・ビュー | 決まり（案） |
|---|---|---|
| 識別子・表題・呼びかけ・型 | `visible_project` | 呼びかけが空なら返さない |
| 作った人 | `visible_project`、`user_profile` | 種類（運営／ユーザー）と今のニックネーム |
| 項目の数 | `project_item` | 企画の項目の全部の数（S15 の並びの数と同じ。指す先が見えない項目も位置として数える） |
| 企画をきっかけにした会話の数 | `visible_conversation`（入口＝この企画で、企画そのものの会話でないもの） | S15 と同じ範囲の公開の会話の数 |

S03・S13 の企画カード（`ProjectCard`）は、ある Discovery・場所との関わり（`matchedBy`・`position`）を持つので、一覧には別の形（呼びかけ・項目の数・会話の数を持つもの）を使う案。

**決めたいこと（レビューで確かめたい）**

1. **絞り込み**：型（すべて／コース／番付／まとめ／記憶。1つを選ぶ）と、作った人（すべて／運営／ユーザー）をクエリで受ける。**地域で絞るのは今回は入れない**（場所との関わりの決め方が要る。TOP の企画の枠の「近くの企画」の条件の引き継ぎと一緒に、S01 の段で決める）
2. **並べ方**：今回は「新しい順」（企画を作った時点の新しい順、同じなら識別子の順）だけを返す。「新しい声の多い順」は、集計の期間・方式を機能の設計で決めてから足す。クエリの並べ方は列挙にし、値を足せる形にする
3. **続き**：1回に20件（暫定）を返し、続きがあればカーソル（並びのキー）を返す。新しい企画が足されても、読んでいる続きの範囲はずれない（新しいものは先頭の側に足される）。絞り込み・並べ方を変えたら、最初から読み直す
4. **全体の数**：返さない（画面は件数を出さない。件数を数える負荷を避ける）。0件なら空の配列（画面が「この条件の企画はまだありません」を出す）
5. **項目の数**：指す先が見えない項目も数える案（S15 の並びの位置の数と合わせる）。見える項目だけを数える案もある
6. **「企画を作る」の見せ方**（一定期間内の作成数の上限に達している人）：認証（#75）のあと。今回の API では返さない

## 判断待ち・検討事項

- 絞り込みの種類（地域で絞るか）と既定の並べ方
- 企画を名前で探すのは、この画面に置かず S02 の「企画」のタブに任せる（決定）
- 「新しい声の多い順」の集計の期間・方式（機能の設計）
- 一定期間内に新しく作れる企画の数の上限に達している人への「企画を作る」の見せ方（累計の上限ではない。2026-11-18 の人の判断、PR #155）
