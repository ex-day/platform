# S03 discovery detail
## 画面概要
指定されたDiscoveryを、評価済みRecommendationに基づき「今ユーザーに最も伝えたい価値」を直感的に提示するHeroを中心に表示する。Heroは画像・映像がなくてもテキスト中心で成立する。HeroはDiscoveryの状態やRecommendationの件数にかかわらず常に表示する（Issue #50）。

## 画面パス
- `/discoveries/[id]`
- `[id]`はモックでは仮ID（例: `sample-1`）を使用する。本番のDiscovery識別子の形式は別途決定する。

## 対象端末
- PC
- モバイル

## アクション
- 初期表示
  - 指定されたIDに紐付くDiscoveryを表示する
  - Discoveryに紐付く価値を取得する
  - 現在のDiscovery ContextとValueのConditionを、必要なDiscovery状態も参照して評価した結果を取得し、表示先へ渡す。評価ロジックはC19に持たせず、評価の実装配置は後続設計で定める
    - 現在成立するValue：評価済みRecommendationと表示に必要な情報をHeroに渡し、価値を直感的なメッセージで提示する
    - 現在成立しないValue：「その他の魅力」としてC12で表示する。順位が低いだけの成立Valueをこちらへ移さない
    - 評価に必要なContext・状態等が不足する場合：成立／不成立を推測しない。評価不能時の表示は検討事項とする
  - 画像・映像がある場合はHeroの主要な視覚情報として利用し、ない場合もValueを伝えるテキストを中心に構成する。Subject・Condition・Discovery状態は表示内容を決める入力情報として扱い、Heroに属性一覧として表示しない
  - 疑問状態では疑問から定義したValueを提示し、声（Post）とともに提供された画像等とともに「一緒に考えませんか？」等の表現を可能とする
  - 複数RecommendationはHero内のサムネイルを選択して切替可能とする
  - Recommendationが0件の場合もHeroを表示する（Issue #50）。起点の写真・資料がある場合はそれをHeroに利用でき、ない場合は探索・情報募集中であることを示す標準Heroを表示する。対象を推測した画像で補完せず、その他の魅力から推薦を補充しない。標準Heroの具体的なデザイン・文言は検討事項とする（Issue #52）
  - 派生元Discovery、派生したDiscovery、関連Discoveryを関係の意味に従って別々の枠に表示する。各枠は0..n件とし、該当がなければ表示しない
    - 派生元・派生先は、現在のDiscoveryを基準に明示的な派生関係の方向で判定する
    - 関連Discoveryには、派生と判定されない明示的な関連およびSubjectを介した意味的関連を表示する。共通Subjectだけから派生とみなさない
    - 各Discoveryの表示にはC03を再利用し、関係種別は枠の見出しで表す
  - わかってきたこと（説・価値）をC25で表示する。0件の場合は表示しない
  - Discoveryのタグを表示する。0件の場合は表示しない
- 声を寄せる（この話に加わる）
    - C26（みんなの声）の入力欄から送ると、このDiscoveryに属する声（Post）として追加される。返信先・タグ・派生先で話す提案等の詳細はC26を参照する
    - 未ログインの場合は、送るときにC08（ログイン認証ダイアログ）でログインを求め、入力内容を引き継ぐ（[DEC-0010](../../decisions/DEC-0010-duplicate-conversations-and-posting-auth.md) 決定2）
    - 送られた声は、[F02（投稿後の会話の解析）](../functions/F02-conversation-analysis.md)の入力となり、結果はC25（わかってきたこと）とC26（みんなの声）の注記・目印に表れる
- 新しい話を始める
    - C01（共通ヘッダー）の「話す」から、[C27（新しい話を始める）](../components/C27-post-new.md)をモーダルで開く。S03のC26の入力欄（この話に加わる）とは区別する
- わかってきたことにリアクション
    - 価値には「わかる」「行ってみたい」、裏付けのない説には「そうかも」を付けられる。裏付けのある説には付けない（DEC-0009 決定9）。詳細はC25・C10を参照する
- 派生の誘導（会話の中の目印、続きの投稿への注記、派生先の冒頭の経緯）を押下
    - 対象のDiscoveryのS03へ遷移する。詳細はC26を参照する
- タグを押下
    - タグを条件にS02 Discovery探索一覧へ遷移する（本PRの案。Issue #67に判断待ちとして記録）
- 「過去のやりとりをすべて見る」を押下
    - C26（みんなの声）の声の一覧を展開する。詳細はC26を参照する
- 関係Discoveryの「さらに見る」を押下
    - S02 Discovery探索一覧へ、該当する関係の条件を引き継いで遷移する
- 遷移元のS01またはS02へ戻る
    - 遷移元のタブ選択状態およびスクロール位置を復元する。時間経過後の順位・鮮度、再取得の基準、非公開となったDiscoveryの扱いは実装時に決定する

## 構成方針
- タイトルとHeroでDiscoveryの入口と現在の価値を示し、わかってきたこと（C25）・本文・リアクション・タグ・その他の魅力・みんなの声（C26）・関係するDiscoveryへつなぐ。詳細な配置はWireframeで検討する。
- 場所は地図を埋め込まず、テキストで表示する。
- リアクションは👍／😮／♥の3種類を併記し、ユーザーが複数の種類を付与できる構成とする。
- 「今のおすすめ」の独立枠は設けず、C13の責務をHeroへ統合する。C13は廃止記録として残し、IDを再利用しない。
- 「その他の魅力」は現在成立しないValueを対象とし、将来・別Contextで成立し得る条件を説明できるようにする。該当がなければ表示しない。
- 公開・推薦上の制約があるValueや評価不能のValueを、一律に「その他の魅力」へ流さない。表示可否・表示先は後続設計で定める。
- 付随的な情報（その他の魅力＝C12、派生元／派生した／関連Discovery＝C03の各枠）は、件数が可変であることを踏まえ横スクロールのカード列として表示する。本文とみんなの声（C26）のみ縦に積む構成とする（DEC-0005、Issue #48のWireframe検証結果）。その他の魅力は、モバイルでは件数によらず横スクロールとし、PC（md以上）ではグリッドで表示する（Issue #50）。関係Discoveryの少数件時の扱いは下記「関係するDiscoveryのモバイル表示」に従う。
- わかってきたこと（C25）は、Hero直後・本文の前に配置する。0件の場合は表示しない。説と価値を分けて示し、説は正解のように見せない（DEC-0009 決定9）。
- 派生の誘導は、C26（みんなの声）の中の目印・続きの投稿への注記・返信するときの提案と、「この発見から広がったDiscovery」の枠の組み合わせとする。続きの会話を派生先で行うよう誘導するが、強制しない（DEC-0009 決定8、Issue #67「判断：派生の誘導の見せ方」）。
- タグは、Discoveryの単位で表示する。声（Post）ごとのタグはC26の中で表示する。タグで見せる単位はDiscoveryとし、SNS的な振る舞いを採らない（DEC-0008 決定4、DEC-0009 決定10）。
- 探索開始直後・探索中・推薦可能のいずれの段階も、別画面や別レイアウトに切り替えず同一画面の延長として表現する。Heroは常に同じ位置に表示し、中身が探索・情報募集の状態から、集まった資料、推薦内容へと成長する。C25・その他の魅力・関係Discoveryは0件を許容し、探索が進むにつれて出現する。みんなの声（C26）は探索中から推薦可能になった後まで継続して表示する（Issue #50のモック検証結果）。「探索開始直後」「探索中」「推薦可能」はView上の表現であり、Discoveryのドメイン状態と一対一に対応しない。ドメイン上の成立状態は`UNESTABLISHED`／`ESTABLISHED`の2状態であり、表示は成立状態・公開状態とValue・Post・Reaction・推薦の算出結果等を組み合わせて決める（[DEC-0006](../../decisions/DEC-0006-discovery-state-responsibilities.md)）。成立の判定条件はIssue #46に従い、本書では定めない。
- その他の魅力・関係Discoveryを横方向へ逃がす構成により、探索中〜推薦可能の各段階でS03全体の縦スクロール量は許容範囲と判断した（Issue #50）。
- みんなの声（C26）は、従来S06（知識・疑問一覧）への遷移で担っていた役割を置き換える。DEC-0005によりPostは会話の中の発言としての参加に一本化されるため、S06への導線は設けない。S05・S06自体の要否は[Issue #68](https://github.com/ex-day/platform/issues/68)で扱い、本書では扱わない。

### 関係するDiscoveryのモバイル表示（ワイヤーフレームレビュー結果）

#### 今回合意した方針
- モバイルでも「派生元Discovery」「派生したDiscovery」「関連Discovery」の3枠を維持する。該当がない枠は表示しない既存方針を継続する。
- 3枠のDiscoveryカード表示は、横スクロールとする。
- 一定件数までは横スクロール内にカードを表示し、表示対象が上限を超える場合は末尾に「さらに見る」に相当する導線を置き、[S02 Discovery探索一覧](./S02-discovery-list.md)へ該当関係の条件を引き継いで遷移できる構成とする。「さらに見る」は探索意思の表れとして扱い、S01の「もっと見る」と同様にS02の責務に含める。専用一覧は設けない。
- 1件など少数件の場合は、無理に横スクロールらしい表現にせず、件数に応じた自然な表示を許容する。
- このレビュー結果はモバイルを対象とし、PC側の表示方式は変更しない。

## 検討事項
- みんなの声（C26）の直近表示件数・展開時の表示件数・ページ送り方式はC26の検討事項とする（Issue #53）。わかってきたこと（C25）を見せる基準と採用（確定）の判断はIssue #61・#46に従う。
- Discoveryのタグの表示件数の上限と並び順、タグによるDiscoveryの露出（S01・S02）の方法
- HeroのRecommendation初期選択、表示順、画像・映像なしの場合と疑問状態の構成
- Recommendation 0件時の標準Heroのデザイン・文言、起点の写真・資料をHeroに利用する条件（Issue #52）
- 現在Contextの基準と再評価契機、評価不能・取得失敗時の表示
- 評価済みRecommendationからHeroの文言・Mediaを用意する担当と入力契約、公開・推薦上の制約と表示の優先関係
- 関係するDiscoveryの3分類の概念は維持する。一方、見出し「この発見のもとになったDiscovery」「この発見から広がったDiscovery」「関連するDiscovery」が一般ユーザーに分かりやすいかは、実データに近いMock等で後続検討する。Non-blocking事項とし、現工程および次工程への引き渡しを止めない。
