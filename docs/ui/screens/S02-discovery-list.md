# S02 探す（検索結果）（search）

> 2026-11-16 根本整理（DEC-0019〜0023、[Issue #135](https://github.com/ex-day/platform/issues/135)）に合わせて書き直した。旧名「Discovery探索一覧」（`/discoveries`）。見せ方（検索結果の一覧）は変えず、探す対象を場所・企画に広げた。v0.3 の定義は Git の履歴にある。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号は候補。

## 画面概要

ユーザーに探す意思があるときに、言葉と条件で、場所・Discovery・企画を探して一覧にする。S01（TOP）が「ex-day が出す」のに対し、S02 は「ユーザーが探す」画面であり、この境界は v0.3 を引き継ぐ（画面一覧「出会う・探す・寄り道の役割分け」）。

S12（寄り道）とは答える問いが違う。S02 は「この言葉・条件に合うものは？」に答え、起点と時間がなくても探せる。到達圏の計算は重いので、全部の結果にはかけず、上位の結果にだけ移動時間を添える（画面一覧、PR #141）。

## 画面パス

- `/search`（条件はクエリで持つ。例：`/search?q=急坂&type=place`）。クエリの名前は API 設計で決める
- 今の実装（`/discoveries`）は v0.3 の形のまま。パスの移行は実装の段で行う（旧パスから新パスへ案内する）
- 座標を URL に出さない。「近く」で探すときは、場所の識別子か既定のエリアで持つ（DEC-0022 決定5）

## 対象端末

- PC
- モバイル

## 探す対象と処理（F07）

| 結果の種類 | 対象 | 使うもの | 備考 |
|---|---|---|---|
| 場所 | Place | 検索のための情報（SearchProfile）、場所の名前・別名・種類 | **言葉に合う場所は、会話や発見がなくても結果に含める**（そこから最初に話せるため。ドメイン設計 3.3節の「画面ごとの表示制御」）。受け皿の粗い場所（町丁・字等）は、言葉に名前が合うときだけ出す |
| 発見 | Discovery | SearchProfile | 公開の Discovery だけ |
| 企画 | Project | SearchProfile | 公開の企画だけ |
| 探しています | 場所が決まっていない会話・問い | 検討中の場所の候補（PlaceCandidate）、回答を募集中の問い（OpenQuestion）、その会話の Post | 「探しています」で絞ったときだけ。SearchProfile は使わない（機能一覧 F07）。それ以外の会話は検索の対象にしない |

## アクション

- 遷移してくる
  - ヘッダーで検索を実行：その言葉で探す
  - S01 の枠の「もっと見る」：枠の条件を引き継ぐ（いま・この時期の発見、近くの発見、番付、声を待っている場所、探しています）
  - S03 の観点を押下：その言葉で探す
  - S03 の関係する Discovery の「さらに見る」：その関係を条件に、発見に絞って出す（v0.3 を引き継ぐ）
- 条件なしで直接開いた
  - 起点（許可済みの現在地の近く、または既定のエリア）の近くのものを、すべての種類で出す。0件なら範囲を広げ、広げたことを出す（v0.3 を引き継ぐ）
- **範囲を自動で広げるのは、既定の地域の条件のときだけ**。利用者が明示的に指定した地域の条件（「鶴見区で」など）は勝手に変えない。指定した地域で0件なら、0件のときの「話す」の案内を出し、地域の条件を外す・広げる操作は利用者に任せる（2026-11-16 の人の判断）
- 条件を変える（言葉・絞り込み・結果の種類）
  - URL を更新して F07 を呼び直す。ブラウザの戻るで前の条件に戻れる
- カード を押下：場所は S13、発見は S03、企画は S15、探しています は S14 へ。戻ると、条件と一覧の位置を保つ
- ここから行ける範囲で絞る を押下：S12 へ。今の検索の条件を引き継ぐ。起点がまだ決まっていなければ、ここで位置情報の許可を求めるか、S12 で起点を選んでもらう
- 0件のときの「話す」を押下：C27 を開く（入口なし）。未ログインでも入力を始められる

## 構成方針

- 見せ方は v0.3 の検索結果の一覧を引き継ぐ（PC は複数列のグリッド、モバイルは1列）。対象が広がっても、見せ方は変えない（2026-11-14 の人の判断）
- 種類の違うカード（場所・発見・企画）を同じ一覧に並べるときは、カードの見た目で種類が分かるようにする（「場所」「発見」「企画」のラベル）
- 移動時間は上位の結果にだけ添え、全部には計算しない。計算の起点の駅を必ず出す（S12「起点と計算の起点」）
- 推定（番付）・見本・ユーザーの企画は、S01 と同じく「推定」「ex-day の発見（見本）」「[ニックネーム] さんの企画」と出す

## 判断待ち・検討事項

- 「すべて」のときの並び（種類を混ぜるか、種類ごとに区切るか）は、実装のあとに比べて決める。種類の違う結果（場所・Discovery・企画）の検索のスコアの比べ方と、混ぜたときの順位付けは F07 の機能の設計で決める
- 移動時間を添える上位の件数
- 件数の上限・続きの読み込み方・取得に失敗したときの表示（v0.3 から引き継ぐ）
- 少数件のときにも「話す」の案内を出すか（v0.3 から引き継ぐ。Non-blocking。Issue #67）
- `/discoveries` から `/search` への移行は、旧 URL の引き継げる検索の条件を保って案内する。正式公開の前なので、移行の仕組みは作り込まない
