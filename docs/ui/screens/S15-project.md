# S15 企画のページ（project）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C40）・機能（F05〜F12）の番号も候補。

## 画面概要

1つの企画（運営のお題、またはユーザーの作品）を見せる。並び（項目と順番・順位、根拠）、作った人、企画そのものの会話、企画をきっかけにした会話を1か所にまとめ、会話の取っかかりにする（[DEC-0021](../../decisions/DEC-0021-projects-by-operator-and-users.md)、[MVP スコープ](../../ex-day_mvp_scope.md) 8節）。

企画は作った人の作品であり、ex-day の認定ではない。作った人を出し、根拠と並べ、人気投票だけで順位を決めない（DEC-0021 決定5）。

## 画面パス

- `/projects/[id]`
- `[id]` は企画の、画面・URL に出す識別子。識別子の形式は物理設計で決める

## 対象端末

- PC
- モバイル

## アクション

- 初期表示
  - 指定された識別子の企画を表示する
  - 企画が非公開なら、一般のユーザーには表示しない（直接の URL でも返さない）。運営は表示でき、非公開であることを出す（画面一覧「運営の権限」）
  - 並びは ProjectItem の順番・順位で出す。項目が指す Discovery が非公開・統合済みなら、統合先へ案内するか、その項目を「表示できません」とする（**案**。論理設計 4.6.1節の要検討）
  - 項目の根拠は、場所の推定の値と、その場所の会話の数から導いて出す
- 項目（場所カード・Discovery カード）を押下：S13（場所のページ）・S03（Discovery のページ）へ
- この場所の話をする を押下
  - C27 を、入口＝この企画で開き、会話の始まりの時点でこの項目の場所を採用する（主体＝会話を始めた人、根拠＝入口。論理設計 4.3節）。場所の共有の誘いは出ない
  - 項目が Discovery を指すときは、その Discovery の出す位置の場所を採用する（**案**。論理設計 4.3節）
- 企画そのものの会話に書く（C26）
  - 返信の確定時に F10 を通す。未ログインなら C08 でログインを求める
  - 「この坂も入れて」などの提案も、ここに声として書く。専用の提案の操作は MVP では作らない（MVP スコープ 8節）
- 編集する を押下：S16 へ（作った人と運営だけ）
- 閉じる を押下（作った人と運営だけ。**案**）：確認のうえ状態を「閉じた」にする。企画そのものの会話は読むだけになり、企画をきっかけにした会話は場所の会話として残る
- 会話カード を押下：S14 へ
- 通報する（C39）：企画を通報する。F10 を呼ぶ

## 構成方針

- 上から「型・状態」「表題・呼びかけ・作った人」「並び（と項目の地図）」「企画そのものの会話」「企画をきっかけにした会話」の順に置く。**PC** は並びを本文の列、項目の地図と企画をきっかけにした会話を横の列にする。**モバイル** は1列
- 作った人は表題のすぐ下に必ず出す。ユーザーの企画は「ex-day の認定ではありません」を添え、運営の企画と見分けられるようにする
- 根拠は並びの横に必ず添え、順位だけを大きく見せない。データから作った番付は、表題か並びの上に「推定」と出どころを出す
- 企画そのものの会話は、並びのすぐ下に置き、「この坂も入れて」「順番はこっちが上では？」と書きたくなる案内文を添える。作った人が読んで、自分で並びを直す（S16）
- 閉じた企画は、並びと会話をそのまま見せ、入力欄と「この場所の話をする」を出さない

## 判断待ち・検討事項

- 作った人が自分で企画を閉じられるか（閉じられる案）。閉じた企画を開き直せるか
- 項目の地図を MVP に入れるか、入れるならどの部品を使うか
- 項目が指す Discovery が非公開・統合済みになったときの見せ方
- 企画そのものの会話の「話す」の扱い（入力欄へ移る案）
- 企画への Reaction（DEC-0021 の要検討。番付の根拠の声の数と混ぜない）は MVP では付けない
