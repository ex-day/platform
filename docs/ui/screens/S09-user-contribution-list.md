# S09 user contribution list
## 画面概要
自分が登録した知識・疑問の履歴を確認し、確認が必要な項目の補完・再確認へ進み、知識・疑問がDiscoveryやValueの形成・向上にどう利用されたかを確認する。Discoveryに未紐付けの知識・疑問も対象とする。ユーザー向けにはContributionを「知識・疑問」と表示する。

## 対象端末
- PC
- モバイル

## アクション
- 初期表示時
  - 本人が登録した知識・疑問を取得し、「確認が必要」な件数を確認する
  - 1件以上ある場合は「確認が必要」でフィルターした状態で表示する。ない場合は「すべて」で表示する
  - 並び順は「新しい順」とする
- 状態フィルター変更時
  - 選択した「すべて」「確認が必要」「Discoveryにつながった」に該当する知識・疑問を表示する
- 並べ替え変更時
  - 選択した「新しい順」「リアクションの多い順」で表示する
- 自分が投稿した知識・疑問レコード押下時
  - S05 知識・疑問詳細画面へ「自分の投稿の確認」コンテキストで遷移する
- 次に必要な操作押下時
  - S05 知識・疑問詳細画面へ「自分の投稿の確認」コンテキストで遷移する。S05の確認・補完導線からS04の編集モードへ進み、S11で場所やDiscovery候補、追加情報を確認・補完する
- 関連Discovery押下時
  - S03 Discovery詳細画面へ遷移する
- 確認が必要な項目の対応完了時
  - 件数と一覧を更新する。確認が必要な項目が0件となった場合は「すべて」に切り替える

## 表示上の注意
- 本画面に検索機能は設けない
- 状態・成果は確定した範囲で「Discoveryにつながりました」「○○の価値向上に利用されました」「この価値を通じて今月12人が△△のDiscoveryにつながりました」など、対象DiscoveryとValueの対応が分かる形で表示する。複数Discoveryの到達人数をContribution全体の単独指標として扱わず、Value成立前や関係・人数が未確定の場合は確定表現をしない
- 確認が必要な場合は「場所を確認してください」など、ユーザーが次に行う操作を示す。単に内部状態名を表示しない
- 状態・成果の算出や判定方法は本画面では定義しない

## 検討事項
- 表示項目の詳細な配置はデザイン時に検討する
- 特定Discoveryについての「つながった人数順」など、Discovery単位の成果に基づく並べ替えは将来候補とし、現時点の対象外とする
- Discovery候補の確認・補完にS05/S04以外の専用フローが必要かは、詳細画面の設計時に検討する
