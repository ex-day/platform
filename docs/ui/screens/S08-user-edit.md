# S08 ユーザー情報更新（user-edit）
## 画面概要
ログインしているユーザーが、自分のユーザー情報を後から確認・変更する画面。ニックネームの変更、地域・興味の登録、ログイン方法の管理、退会を行う。

- ニックネームの**初回登録はS07（初回のニックネーム設定。#75の決定後に定義）**で行う。S08は、登録済みの情報を後から変える画面であり、投稿の前に必ず通る画面ではない（Issue #74「判断：ニックネームを必須にする」）。
- 使い道のない情報は持たない（Issue #76）。旧定義の「年代」「性別」は削除した。
- 認証プロバイダから受け取る名前・顔写真は使わない。初期値にもしない（Issue #75「判断：プロバイダから受け取る名前・顔写真は使わない」）。公開される名前は、ユーザーがex-dayで自分で決めたニックネームだけとする。
- ユーザー名（重複不可の識別用の名前）は持たない。内部の連番（主キー）は画面・URLに出さない（Issue #74「判断：ニックネームの重複を許す・ユーザー名は持たない」）。

## 画面パス
- `/account`（ログインしているユーザー本人のみ。URLにユーザーの識別子を含めない）

## 対象端末
- PC
- モバイル

### ニックネームの入力のルール（Issue #74「判断：ニックネームの文字数・禁止語・変更回数」）
| 項目 | ルール |
|---|---|
| 必須 | 空にできない（前後の空白を削った結果が空の場合も不可） |
| 文字数 | 全角12文字（半角24文字）相当まで。全角＝2、半角＝1、絵文字＝2と数え、合計24まで（英数字だけの名前が不当に短くならないように） |
| 使えない文字 | 改行、制御文字 |
| 前後の空白 | 自動で削る |
| 重複 | 許す（他の人と同じニックネームでもよい） |
| 禁止語 | 「ex-day」「運営」「公式」を含む名前（運営と紛らわしい名前）。全角・半角、大文字・小文字、ハイフンの有無等をそろえてから照合する（例：「EXDAY」「ｅｘ－ｄａｙ」も対象） |
| 「ななしさん」 | 使ってよい |
| その他の不適切な語 | 悪用対策・モデレーション（[Issue #35](https://github.com/ex-day/platform/issues/35)）の方針に従う |
| 変更回数 | 制限しない |
| 表示上の省略 | 上限内でも、声の見出し行より狭い場所（通知の一覧、返信先の中身の表示等）では末尾を「…」で省略する（表示側の扱い） |

基準は「スマホのC26（みんなの声）の声の見出し行で見切れないこと」とする。

## アクション
- 初期表示時
  - ログインしていない場合は、C08（ログイン認証ダイアログ）でログインを求める
  - 現在のニックネーム、よく知っている地域、興味のある地域、興味のある〇〇、ログイン方法を表示する
- よく知っている地域・興味のある地域を入力
  - 地名を入力すると、市区町村程度の地域を補完して示し、選んで追加する。複数追加でき、個別に外せる（補完の元データ・粒度の詳細は検討事項）
- 興味のある〇〇を入力
  - Issue #73の結論に従う。案では、入力に応じて保管されているタグを補完し、選んで追加する。該当がなければ自分の言葉で追加する。複数追加でき、個別に外せる
- 更新押下時
  - 入力をチェックし、問題があれば該当項目の近くに理由を示して更新しない
    - ニックネームが空（前後の空白を削った後）
    - ニックネームの文字数が上限（全角＝2、半角＝1、絵文字＝2で合計24）を超える
    - ニックネームに改行・制御文字が含まれる
    - ニックネームが禁止語（「ex-day」「運営」「公式」を含む。表記の揺れをそろえて照合）に当たる、またはIssue #35の方針で不適切とされる
  - ニックネームの前後の空白を削ってから保存する。重複の確認は行わない
  - 更新処理を実施し、更新後のユーザー情報を表示する
  - 声（Post）の表示名は、表示のたびにユーザーの今のニックネームを引いて（JOINして）表示する。投稿時の名前を声に保存しないため、ニックネームの変更は過去の声の表示にもすぐ反映される（Issue #74）
  - ニックネームを変更した場合、変更前後の名前と日時を**アカウント単位の変更履歴**として保持する。変更履歴は本人・他の利用者には見せず、運営だけが閲覧できる（監査。名前を変えて逃げる荒らし等への対策。Issue #74・#35）
- ログイン方法の追加・つなぎ直し
  - 詳細はIssue #75の判断待ち。プロバイダから受け取る名前・顔写真は取り込まない
- 退会押下時
  - 退会すると元に戻せないこと等の警告を表示する
  - 退会処理を実施する
  - 処理端末にかかわらず S01（Discovery提案（サービスTOP））へ遷移する

## 検討事項
- 【判断待ち】興味のある〇〇の項目名・登録の単位（声のタグ・内部で持つタグ・観点のどれか）・入力方法・使い始めの時期の扱い（Issue #73）
- 【判断待ち】ログイン方法の項目の詳細（表示する内容、追加・つなぎ直し・外す操作、最後の1つを外せないようにする等。Issue #75）
- 【判断待ち】退会時の投稿済みの声（Post）の扱い（残す場合の表示名、削除する場合の会話・わかってきたことの出所・判断記録に固めた根拠への影響。DEC-0009 決定1）と、ニックネームの変更履歴等の保持期間
- 【判断待ち】地域の粒度と入力方法の詳細（市区町村の補完の元データ、市区町村より広い・狭い地域を入れたい場合の扱い）
- よく知っている地域を使って「この地域を知っている人」に問いを届ける方法（通知の見せ方・頻度）は後続設計とする。届ける場合も、その人の地域を他の人に見せない
- アイコン（顔写真）の扱いは別途とする（Issue #75。プロバイダからは取り込まない）
- ニックネームの見直しの条件（Revisit）：ニックネームの登録で離脱が多いことが実データで確認された場合は、未設定を認める形を再検討する（Issue #74）
