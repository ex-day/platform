# S13 場所のページ（place）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C40）・機能（F05〜F12）の番号も候補。

## 画面概要

1つの場所について、その場所の発見（Discovery）、会話、場所が決まっていない話（このあたりで探している人がいます）、その場所が入っている企画、ここから行ける範囲（寄り道）を1か所にまとめて見せる。場所は Discovery や会話がなくても存在するので（[DEC-0020](../../decisions/DEC-0020-place-conversation-discovery.md) 決定1）、発見も会話もない場所でも開け、「最初に話す」入口になる。

場所はどこかだけを表し、「何としての話か」は Discovery の Subject・Value が表す。同じ場所に、観点の違う発見が並ぶ（小机城址：空堀の歴史と、春の桜の穴場。ドメイン設計 9.2節）。

## 画面パス

- `/places/[id]`
- `[id]` は場所の、画面・URL に出す識別子。座標を URL に出さない（[DEC-0022](../../decisions/DEC-0022-top-page-and-detour-entry.md) 決定5）。識別子の形式は物理設計で決める

## 対象端末

- PC
- モバイル

## アクション

- 初期表示
  - 指定された識別子の場所を表示する
  - 場所の状態が統合済みなら、統合先への案内を出す（自動では移動しない。**案**）。廃止の場所は、存在した期間があればそのまま表示する
  - 採用されていない場所（新しい場所の案）は Place ではないので、このページを持たない（論理設計 4.2節）
  - ここでの発見は、DiscoveryPlace でこの場所が関わる、公開の Discovery を出す。非公開・統合された Discovery は出さない（運営は C38 から見られる）
  - このあたりで探している人がいます は、検討中の場所の候補（対象が会話・問い）から導く。資料の撮影場所の候補は MVP では出さない（資料は二次開発）
  - この場所の会話は、採用中・再検討中の場所の採用（PlaceAdoption）でこの場所と紐付く会話から導く（論理設計 4.3.1節）
  - 小さな地図は、F06（寄り道の到達圏）でこの場所を起点にした範囲を出す。計算できないとき（駅から遠い、データがない）は、位置だけを出す
- 話す を押下
  - C27（新しい話を始める）を、入口＝この場所で開く。会話の始まりの時点で、この場所の採用（主体＝投稿した人、根拠＝入口）を作るので、場所の共有の誘い（C31）は出ない（論理設計 4.3節、[DEC-0023](../../decisions/DEC-0023-no-place-input-on-post.md)）
  - 未ログインでも入力を始められ、確定時に C08 でログインを求める（DEC-0010 決定2）
- ここから行ける・小さな地図 を押下
  - S12（寄り道）へ。`from`＝この場所。戻るとこのページの表示位置を保つ
- 発見 を押下：S03（Discovery のページ）へ
- 探していますのカード・会話カード を押下：S14（会話のページ）へ
- 企画カード を押下：S15（企画のページ）へ
- 場所の階層・このあたりの場所 を押下：その場所の S13 へ
- 統合先への案内 を押下：統合先の S13 へ

## 構成方針

- 上から「場所の見出し（階層・名前・種類・存在した期間）」「小さな地図と行き方」「話す・ここから行ける」「ここでの発見」「このあたりで探している人がいます」「この場所の会話」「この場所が入っている企画」「この場所のデータ」「このあたりの場所」の順に並べる。中身のない区画は出さない（DEC-0022 決定2 の考え方を場所のページにも当てはめる）
- **PC**：本文の列（発見・探しています・会話）と、横の列（小さな地図、行き方、話す・ここから行ける、企画、データ、このあたりの場所）に分ける。**モバイル**：1列。小さな地図と「話す」「ここから行ける」を見出しのすぐ下に置く
- ここでの発見は、観点（Subject の観点）ごとに見出しを付けてまとめる。観点が1つしかなければ見出しを省く。同じ Discovery を複数の観点に重ねて出さない（**案**：主な観点1つに入れる。どれを主にするかは F07 の SearchProfile か Discovery の Subject の並びで決める。要検討）
- 発見のカードには、この場所の役割を添える（「記憶の場所」「今の跡地」「体験できる場所」「始まり」）。役割がこの場所の上で意味を持たない場合（体験できる場所が1つだけ）は省いてよい
- このあたりで探している人がいます は、目立つ色の区画にし、「場所がまだ決まっていない話です。心当たりがあれば教えてください」を添える（キャンバス「候補の場所のページ：探しています」）
- 推定の値は「推定」と出どころを必ず添え、ex-day の認定に見せない
- 発見も会話もない場所（寄り道の「声のない場所」、番付の項目の坂など）でも、このページを開ける。その場合は、場所の見出し・小さな地図・データ・企画の下に、最初の声のお誘いを出す
- 場所の候補への「ここかも」「違うと思う」は、このページでは押せない。S14（会話のページ）で行う（判断の材料として根拠の Post とともに残すため）

## 判断待ち・検討事項

### 決めたこと（2026-11-17 の人の判断、PR #153 のレビュー）

- **統合済みの場所**：自動で統合先へ移さず、統合先への案内だけを出す。新しい会話（話す）と最初の声のお誘いは出さない。廃止の場所では出せる
- **観点ごとのまとめ**：1つの Discovery を、観点の名前の順で最初の観点にだけ入れる。**MVP の暫定の表示の決まり**であり、ドメインの「主な観点」を決める規則ではない。まとめる前に、成立の新しい順に30件を選ぶ（観点の名前の順で対象が偏らないようにする）
- **この場所の会話の並び**：会話を始めた時点の新しい順。最初は10件。返信の多さによる人気の順にはしない
- **場所の階層**：行政の階層を先にたどり、なければ地理的な包含をたどる。この場所自身・通った場所は含めず、10段まで
- **新しい場所の案（このあたりで探している人がいます）**：エリアの場所のときだけ、案の位置が範囲に入るかで判定する。地点・経路の場所への距離による関連付けはしない
- **このあたりの場所**：保存した場所どうしの関係だけを使う。位置から計算する包含（空間の検索）で補わない

### 将来の検討事項（今は作らない）

- **観点の分類と表示の順**：観点の優先度は人の興味によって違い、いつもの興味だけでなく、そのときの検索の目的や遷移元によっても変わり得る。興味のない観点が先頭に来ると離れてしまうおそれもある。パーソナライズはもとの構想にあるが、今のシステムの規模・複雑さを考えて、今は作らない（追加のデータ構造やパーソナライズの仕組みも作らない）。画面を作り、コンテンツを入れて操作したうえで、分類の仕方・表示の順を見直す
- 会話の続きを S13 の中で読み込む API（必要になったときに足す）
- 地点・経路の場所への、距離による探している話の関連付け、空間の検索による「このあたりの場所」の補完
