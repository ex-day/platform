# S14 会話のページ（conversation）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C40）・機能（F05〜F12）の番号も候補。S05（知識・疑問詳細。廃止）の代わり。

## 画面概要

1つの会話（投稿と返信のまとまり）を見せ、その場で返信できるようにする。会話の中で出てきた場所の候補とその採用、問いと回答の採用、会話から分かってきたこと、会話から生まれた発見を、会話と一緒に見せる。ex-day の E（会話）の中心の画面で、A（地域の記憶）・C（今昔）が持ち寄られ、D（体験へ誘う）につながる場所である（[DEC-0019](../../decisions/DEC-0019-what-ex-day-wants-most.md)）。

場所が決まっていない会話も正常な状態であり（[DEC-0020](../../decisions/DEC-0020-place-conversation-discovery.md) 決定3、[DEC-0023](../../decisions/DEC-0023-no-place-input-on-post.md)）、このページで周りの人が「ここでは？」と答えて場所が採用されていく。

入口（場所・Discovery・企画）がある会話は、まず入口のページに出る（居場所。ドメイン設計 3.4節）。このページは、入口があってもなくても、すべての会話が持つ。

## 画面パス

- `/conversations/[id]`
- `[id]` は会話の、画面・URL に出す識別子。識別子の形式は物理設計で決める

## 対象端末

- PC
- モバイル

## アクション

- 初期表示
  - 指定された識別子の会話と、その Post を表示する
  - 会話が非公開なら、一般のユーザーには表示しない（直接の URL でも返さない）。運営は表示でき、非公開であることを出す（画面一覧「運営の権限」）
  - 非公開の Post は、一般のユーザーには「この声は表示されていません」として場所だけ残す（**案**。会話の流れが分からなくなるのを避ける）
  - 場所の状態は、採用中・再検討中の場所の採用から導く。入口から決まった場所も同じく採用として出す（論理設計 4.3節）
  - 「あとで」にした場所の共有の誘いから来たとき（S09 から）は、場所の候補と採用（C33）の場所を選ぶ操作を開いた状態で出す
- 返信する
  - C26 の入力欄から送る。本文だけを書き、場所は入れない（DEC-0023）
  - 確定時に F10（禁止語のチェック、暫定公開）を通す。未ログインなら C08 でログインを求め、入力内容を引き継ぐ（DEC-0010 決定2）
  - 送った返信は F02（会話の解析）の入力になり、結果はあとで C25・C33・C34 に出る。投稿の直後の地名の照合（F05）は、返信では場所の候補だけを作り、場所の共有の誘いは出さない（誘いは会話を始めた Post だけ。論理設計 4.4.4節）
- 場所の候補に声を寄せる（C33）
  - 「ここかも」「違うと思う」を押す。ログインが要る。声は候補の根拠とは別に、判断の材料として残る
- 場所を指して答える（C33）
  - C32（場所を選ぶ部品）で地図を指す・近くから選ぶ・既存の場所を名前で探して選ぶ。同じ場所の候補がすでにあれば、新しい候補を作らず、その候補に根拠と声を足す（論理設計 6.1節）。返信の Post と一緒に送る（**案**：根拠の Post を必ず残すため）
- 場所を採用する・採用し直す・再検討中にする・取り消す（C33）
  - F08（場所の採用）を呼ぶ。操作できる人は、対象が問いなら問いを立てた人、対象が会話なら会話を始めた人（**案**）、どちらもいない・応じないときは運営（「現在有力」）
  - 採用中の場所に新しい異論が寄せられても、自動で取り消さず「再検討中」と出す
- 回答を採用する（C34）
  - 場所を探す問いは C33・F08、場所以外の問いは F11 を呼ぶ。操作できるのは問いを立てた人、いない問いは ex-day の規則・運営
  - 問いへの「自分も気になる」は C10 で付ける（論理設計 4.7節）
- わかってきたことにリアクション（C25）
  - 価値には「わかる」「行ってみたい」、裏付けのない説には「そうかも」。裏付けのある説には付けない
- 通報する（C39）：会話・Post を通報する。F10 を呼ぶ
- 入口・場所の状態・発見 を押下：入口のページ、S13、S03 へ
- 届くところ を押下：候補の場所の S13、TOP（探しています の枠）、S09 へ

## 構成方針

- 上から「入口と場所の状態」「会話の投稿と返信（返信の入力欄まで）」の順に置き、**会話を主役にする**。場所の候補と採用・問い・わかってきたこと・生まれた発見・届くところは、PC では横の列、モバイルでは会話の下に置く
- 場所が決まっていない会話では、問いと場所の候補を会話の上（PC では横の列の一番上）に出し、「探しています」の目立つ色の区画にする（キャンバス「会話のページ：水車のそば屋」）。「場所を指して答える」を返信の入力欄の横にも置く
- 採用した場所・回答は、「採用」「投稿者が採用した回答あり」「現在の回答あり」「新しい情報が寄せられ、再検討中」と出し、「確定」「解決済み」「答えが出た」と言わない（ドメイン設計 1.2節）。不採用・取り消しの候補も、折りたたんでたどれるようにする
- わかってきたことは、会話から ex-day が読み取ったもの（見立て）だと分かるようにし、説を正解のように見せない（DEC-0009 決定9）
- 会話を始めた Post は、返信と対等に扱う（DEC-0008 決定2）。最初の Post だけ大きく見せることはしてよいが、別の種類のものとして扱わない
- 返信が多い会話は、最初の Post と新しい返信を出し、間を「これまでのやりとりを見る」で開く（v0.3 の C26 の考え方を引き継ぐ）

## 判断待ち・検討事項

- 会話の話の場所（対象＝会話の場所の候補）を採用できる人：会話を始めた人とする案。会話を始めた人がいなくなった・応じないときの扱い
- 「場所を指して答える」で、返信の Post を必須にするか（根拠の Post を残すため必須とする案）
- 非公開の Post の残し方（「この声は表示されていません」と場所だけ残す案）
- 似た話（キャンバスの「似た話」）は MVP の対象外（F03 と同じ理由）
- 入口がある会話で、このページに直接来た人に入口のページへの案内をどれだけ強く出すか
