# S18 運営の管理（admin）

> 2026-11-16 新規（[Issue #135](https://github.com/ex-day/platform/issues/135)）。画面 ID は画面一覧のとおり案（人がレビューで確定する）。本書で使う新しいコンポーネント（C28〜C41）・機能（F05〜F12）の番号も候補。

## 画面概要

運営が、確認・介入の要るものを一覧で見る画面。**一覧が要るものだけの最小限**にする（2026-11-14〜15 の人の判断、[MVP スコープ](../../ex-day_mvp_scope.md) 12節）。詳細の確認と直しは、一般の画面（S03・S13・S14・S15）を運営の権限で共用し（C38。画面一覧「運営の権限」）、足りないところは運営が SQL・データの投入で補う。運営用の MCP サーバーは 1.5次開発（MVP スコープ 14節）。

運営は知識の正しさを裁定する存在ではなく、知識が安全に蓄積される環境を保つ存在である（機能一覧「F10 の後続検討」）。

## 画面パス

- `/admin`（一覧の切り替え。例：`/admin/reports`、`/admin/auto-discoveries`）。運営の権限（Cognito の運営のグループ）が要る。一般の画面からの遷移は持たない

## 対象端末

- PC（モバイルは MVP では対象にしない。**案**）

## アクション

- 初期表示：運営の権限がなければ表示しない（一般の画面へ戻す）。権限の判定はサーバー側で行う
- 一覧の項目 を押下：対象の一般の画面（S03・S13・S14・S15）を、運営の権限で開く。非公開・統合済み・取り消された対象も開ける（画面一覧「運営の権限」）
- 対応の状態・見直しの状態を変える：判断の記録を足す（前の記録を書き換えない）
- 非公開にする・戻す、成立の取り消し、付け替え、統合、場所の採用の直し：S18 ではなく、開いた一般の画面の C38 で行う（F08・F10・F12）

## 構成方針

- 一覧と、一般の画面への入口だけを持つ。直しの操作を S18 に重ねて作らない
- 自動で成立した Discovery は、見直しのしやすさを優先し、由来の会話と適用した規則・解析の版を一覧から見えるようにする
- 通報の一覧では、内容への異論（知識の正誤）ではなく、規約違反・権利侵害・安全上の問題を扱う（S03「リアクション・会話・通報の役割」）
- 最低限要る管理の画面は開発の完了までに決め、それまでは SQL・データの投入で補ってよい

## 判断待ち・検討事項

- 通報の対応の状態の種類、見直しの状態を持つか（F10・F12 の設計）
- 企画の暫定公開と事後チェックの一覧を、通報の一覧と同じにするか分けるか
- 作った人が非公開の企画を直したことを、事後チェックの一覧で分かるようにする（S16 の案）
- 安全性に関する公開制御（通常公開・注意喚起付きの公開・非公開）を入れるときの、この画面の扱い（F10 の後続検討）
- モバイルを対象にするか
